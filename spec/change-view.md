# The change view: rows, folding, side by side, word diff, navigation

Read this when touching `umain.diffview.inc`, `BuildChangeView`, `ShowChanges`, line numbers, gaps, Hide Unchanged Lines, Side by Side, `gittan.worddiff`, F7 stepping, folding.

- Selecting a file calls `ShowChanges`: `FileChanges` runs `git diff --no-renames -U99999999 <base> -- path` so the whole file is one hunk, with deleted lines kept in place. When git cannot give the diff (a file it cannot read, say) `ShowChanges` returns False: the banner shows git's message and the summary is shown with nothing selected in the tree, so the tree, the header and the text never name different files; the selection handler then skips `GoToFirstChange` and a refresh its scroll restore. The lines with their markers are kept in `FChangeLines`, and `BuildChangeView` in `umain.diffview.inc` turns them into the editor's rows (`FRows`, `TGittanRow`). The `+`/`-` markers are stripped from the text and become line backgrounds (green added, red deleted) through the editor's second bookmark list (`BookmarkSetForLine_2`), whose entries color a line without a gutter icon; `OnCalcBookmarkColor` maps the kind to the color. An untracked file is read from disk and shown all green. The raw repository diff gets the same colors on its `+`/`-` lines.
- View > Hide Unchanged Lines (Cmd+Shift+U) keeps only the changed lines with View > Context Lines (1, 3, 5 or 10) around them. The hidden lines stay in the text, so the lexer parses the whole file (a comment that starts in a hidden line still ends where it should), marked with `Strings.LinesHidden`, the editor's own folding flag: the wrap info leaves them out, `WrapStructInvalidate` and `Update(True)` rebuild it. Each run of hidden lines gets a gap row before it ("⋯ N unchanged lines ⋯", bookmark kind `bmGap`, no line number); a click on it (`EditMouseUp`, the caret is on the clicked row by then) adds the run to `FExpanded` and rebuilds the view (`ExpandGap`). A run longer than `GapStep` (20) lines also carries the labels "↓ 20", "↑ 20" and "all" (`GapRowText`, which answers the column each starts at, in UTF-16 units like the caret): a click on the first opens the first 20 hidden lines, so the text above goes on, the second the last 20, the third or the description the whole run; the rest stays a gap row, since the builder makes one for every run of lines not kept.
 The gaps opened are kept while the same file is shown again, as on a refresh. The caret must never sit on a hidden row (the editor would unfold the lexer range around it): `VisibleRow` moves it to the next shown row wherever a row index is restored.
- View > Side by Side (Cmd+Shift+S) shows the old side in `FEditOld`, a second `TATSynEdit` with its own adapter (`FAdapterOld`, an adapter parses one text) left of the editor, with a splitter (`FSideRatio` keeps its share). `BuildChangeView` pairs the rows: a context or gap row goes to both sides, a run of deleted lines and the run of added lines after it go to the old and the new side, the shorter padded with filler rows (`bmFiller`, blank, no number). The old side numbers its lines from the old file (a deleted line's number in red), the new side from the new. `ChangeBlocks` ignores gap rows and counts a filler as part of its block, so the navigator still counts changes. `EditorScroll` keeps the two in step on the user's scrolling; `SyncOldSide` does it after every programmatic move (it also sets `LineTopTodo` and runs again from the message loop, since an old side just shown has no wrap info and its resize resets the line top at the next paint). Word wrap is off while both sides show, since wrapped rows would not line up. Every editor helper (`ShowText`, `MarkLine`, `SetRowNumbers`, `ResetLineNumbers`, `UpdateNumberWidth`, `SetLineStatesBand`, `ApplyEditorColors`) takes the editor as a parameter; `SetupEditor` applies the shared options to both, and zoom (View > Zoom In/Out/Actual Size, or the mouse wheel) and View > Font… apply to both. Each ends in `EditorMetricsChanged`, which sizes the number and blame bands from the new character width and gives the Markdown preview the editor's size (`TGittanMarkdownPreview.SetFontSize` loads a shown page again, since the page takes the size as it loads): the wheel through `OnChangeZoom` (`EditChangeZoom`), the menu's Zoom In and Out by calling `EditChangeZoom`, since `DoScaleFontDelta` fires no event, and Actual Size and the font directly.
- Go > Next/Previous Change (F7, Shift+F7) go on to the next or previous changed file in the tree (`StepFile`) past the last or first block, and wrap around in the file only when there is no other file; Go > Next/Previous File (F8, Shift+F8) step files directly.
- Scrolling on with the wheel (or trackpad) at the bottom of a file in the change view pulls in the next file (`EditMouseWheel` in `umain.actions.inc`, set on both editors; `NeighbourFile` finds the node, `StepFile` uses it too). The LCL's `OnMouseWheel` fires before ATSynEdit scrolls, so a wheel step that already sits at the bottom (`ScrollVert.SmoothPos` at `SmoothPosLast`) adds its delta to `FOverscroll`; one that scrolls, or scrolls up, resets it, and `FOverscrollTimer` forgets a pull left half way after `OverscrollForget` ms. At `OverscrollNeeded` (600: five notches of a mouse wheel, about 75 px of a trackpad, since Cocoa's LCL scales a precise delta to 8 per pixel) the next file is shown from its top. A trackpad's momentum runs on after the jump, so the pull is disarmed until the wheel has paused `OverscrollPause` ms (`FOverscrollArmed`). `EditDrawEditor`, the editor's `OnDrawEditor` hook, paints a pill ("Next: name ↓") that rises from the bottom edge of the text and fills from the left with the pull; its colors (`FPull*`) are set in `ApplyTheme` beside the navigator's. There is no pull up to the previous file: after a jump the view sits at the top, where a momentum tail would bounce straight back.
- The change view numbers its lines itself (`SetRowNumbers`): the editor's own numbering would count the deleted lines kept in the text, so every line below a deletion showed a number too high. ATSynEdit has no hook for the number text, but its gutter decor (`GutterDecor`) draws a text per line in the bookmark band. So the number band is hidden, the bookmark band is widened to the widest number (`OptGutterWidthBookmarks`, reapplied by the editor on every update, so the option is set rather than the band), and each row gets its number as decor text; a deleted line (in the unified view), a gap, a filler and a hidden row get none. An added line's number takes the strip's green (the decor's `Tag` keeps the kind, `LineNumberColor` maps it). `ResetLineNumbers` restores the editor's numbering for the file view and the repository diff, `ApplyTheme` recolors the decor, and `OnChangeZoom` resizes the band. The number style is `All` so both views look alike. `UpdateNumberWidth` measures the character width itself (`EditorCharWidth`, a bitmap canvas with the editor's font at its zoom): the editor's `TextCharSize` is a placeholder until its next paint, and the first change view is built before the editor has ever painted (the summary hides it until then), so a band sized from it cut the numbers once the editor reapplied it.
- `ChangeBlocks` in `umain.pp` lists the first line of every block of added/deleted lines from the second bookmark list; `GoToChange` jumps to the next or previous block from the caret and scrolls it near the top. The Go menu binds them to F7 and Shift+F7. `UpdateChangeNav` hides the pill while the list is empty and sets the counter to the last block the caret has reached. It runs from the editor's `OnChangeCaretPos`, but through `Application.QueueAsyncCall`: the event fires inside the editor's own updates, and resizing a child there (the pill grows with its counter, and was the editor's child then) made the editor recompute its scroll position from a half-updated state and scroll sideways after a theme change.
- The gutter's line states band (3 px, between the numbers and the fold icons) is the diff's strip: `MarkLine` sets an added line to `TATLineState.Added` and a deleted one to `Changed`, and `ApplyTheme` sets `Colors.StateAdded` green and `Colors.StateChanged` red. ATSynEdit marks every line of a freshly set text as `Added`, so `ShowText` resets the states to `None` before the marks and shows the band through `SetLineStatesBand`; `OpenFile` and `FormCreate` hide it, since a plain file has no changes.
- The gutter's fold band is shown where `FoldingShown` allows: in the file view, and in the unified change view while View > Hide Unchanged Lines is off (`SetFoldBand`, from `ShowEditor` and `BuildChangeView`), its icons only under the mouse (`OptGutterShowFoldAlways` off). A click folds the lexer's range (a function, a class, a section) to its first line, drawn dimmed in a grey frame (`CollapseMark*`). View > Folding has Fold and Unfold at the caret (Cmd+Alt+-, Cmd+Alt++) and Fold All and Unfold All (with Shift), the editor's own fold commands by the item's `Tag` (`MenuFoldClick`); the menu is enabled, and the shortcuts act, only where `FoldingShown`. A find, a Go to Definition (`FoldAction`) or F7 that lands in a folded line unfolds it there; elsewhere a hidden line is the diff's and stays hidden. A refresh or a view option rebuilds the text: `KeepFolds` remembers the folded ranges by the file line they start on (`FileLineOfRow`: the row in the file view, `FNewNum` in the change view) and `RestoreFolds`, from `AdapterParseDone`, folds them again once the lexer has parsed the same file. Hide Unchanged Lines, Side by Side and the history view keep the band hidden: they hide lines through the folding mechanism (below), which a fold or unfold of a lexer range would disturb, or line up two editors row by row. Folding stays enabled (`OptFoldEnabled`): the wrap info skips hidden lines only then, and the adapter adds no fold ranges without it.
- The diff line colors in `EditCalcBookmarkColor` are faint tints of the editor background (GitHub's values for light, the same blended onto the dark palette), so the lexer's syntax colors still read on top of them.
- `gittan.worddiff.pp` holds `WordDiff`: for every run of deleted lines followed by added lines it tokenizes both runs (words, runs of spaces, single punctuation characters, a break token per line end), takes a longest common subsequence of the tokens, and returns the unmatched tokens as character spans per diff line (UTF-16 units, as the editor counts columns; adjacent spans and spans with only spaces between them are joined). A block whose sides share less than `MinCommon` of their text (rewritten, not edited) and a block over `MaxBlockLines` or `MaxCells` token pairs get no spans. `BuildChangeView` computes `FWordSpans` from `FChangeLines`, `FillChangeEditor` puts them on the shown rows through `MarkWords`, and `ShowRepoDiff` does the same on the raw diff with the spans shifted one column for the marker (its hunk and file header lines get a blank marker first; a file's header runs from its `diff` line to its first `@@`, so a `---`/`+++` line in a hunk, a deleted `-- comment` or an added `++i;`, is a change like any other). `MarkWords` uses the editor's attribs (`Attribs.Add` with a `TATLinePart` that sets only `ColorBG`, so the lexer's text color stays), tagged `tagWordAdded`/`tagWordDeleted`; `WordColor` gives the shade for the theme and `RecolorWords` in `ApplyTheme` recolors the existing marks. Setting `Text` clears the attribs, so `ShowText` needs nothing extra.
- View > Ignore Whitespace (Cmd+Alt+I, `IgnoreWhitespace` in the settings) sets `TGittanRepo.IgnoreWhitespace`, which `RunDiff` turns into `-w` on every `git diff`: the numstat counts, the file diffs and the repository diff all leave whitespace changes out, and `WordDiff` then treats two runs of spaces as equal. The toggle runs `RefreshRepository`. `FileChanges` with an empty diff asks `git ls-files` whether the file is tracked: a tracked file (its changes whitespace only, or a mode change) is shown with every line unchanged, an untracked one all added. The watcher's own repository runs without the flag; it only needs to notice a change.
- The editor is a viewer: `ModeReadOnly` is set in `FormCreate`. ATSynEdit silently ignores `Text` and `LoadFromFile` while read-only, so `ShowText` and `OpenFile` clear the mode around the load and set it again. Loading does not clear the second bookmark list, so they call `BookmarkDeleteAll_2` first. There is no Save command.
