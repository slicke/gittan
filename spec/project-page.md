# The Project page

Read this when touching `gittan.projectpage`, `umain.project.inc`, the Project row of the sidebar, View > Project, or Add to .gitignore on a check. What a kind of project is, its dependencies, its lock file and its checks are in project-kinds.md; the Commands page that runs a kind's tools in repo-commands.md.

- The page shows what the repository is as a project: the seventh row of the sidebar (`navProject`, after Pull Requests, which hides without a forge; `niProject`, a box seen from above a corner) and View > Project (Cmd+Option+7, Ctrl+Shift+7 elsewhere; `MenuProjectClick`). `TGittanProjectPage` (`gittan.projectpage.pp`) is painted like the Commands page in the same scroll box (`FView = gvProject`; `ShowProject` in `umain.project.inc`): the repository's name and root, then one section per kind found (`TGittanProjectReport`, project-kinds.md), its heading the kind's name, the file that told it, the project's version and how many dependencies it has, and at the right end how many changed since the tag in the link color ("4 changed since v0.1.0"), or "no changes since v0.1.0" dimmed, nothing without a tag. Under the heading the dependencies as rows: the name in bold, a link to the package on the kind's registry (`PackageUrl`; `OnOpenUrl`, `OpenURL`) with the address as its hint; what the manifest asks for, dimmed; what the lock file resolved it to, when it has one that differs from what is asked for (go.mod asks for the exact version); and at the right end the change since the tag: "added" in the ok color, "removed" in the error color (the row dimmed, with the old version), "1.0.200 → 1.0.210" in the link color, each with a hint saying when ("serde was 1.0.200 at v0.1.0"). The plain dependencies come first under no heading, then each group under its title (`GroupTitle`: Development, Build, Peer, Optional, Indirect, else the group's name with a capital), the removed ones of a group at its end; the name and version columns are as wide as their widest text within `NameShare` and `VersionShare` of the width. A kind with nothing to read says so (`rsNoDependencyFile`, setup.py alone) and one with a file but no dependencies too. Under them the checks (`PaintChecks`) in a card: a disc in the warning color, the text wrapped, and Add to .gitignore at the right when the check has a pattern (`OnIgnore` with the check). With no kind the page says what it looks for (`rsNoProject`) and that a `project =` line of commands.ini names one.
- Add to .gitignore (`ProjectPageIgnore`) writes the pattern to the root's .gitignore as the file menu's item does (`AddIgnorePattern`) and takes the tracked files the pattern covers out of the index (`TrackedFiles`, then `RemovePaths` with keep, git rm --cached: the files stay on disk), since an ignored file git tracks is still tracked and the check would stay: a pattern ending in "/" covers the paths under that folder at any depth, "*.ext" the paths with that extension, any other the check's own path. The status bar says what was added and how many files stopped being tracked; the checks are built again with the snapshot the reload brings.
- `LoadProject` builds the reports: `NearestTag` (git describe --tags --abbrev=0, the newest tag reachable from HEAD; none gives no comparison), the tracked files, and for each kind in `FRepoProjects` (the kinds `LoadRepoCommands` found, so the `project =` line of commands.ini counts here too) the dependency file and the lock file as they were at the tag (`FileBlob`; '' for one that was not there), handed to `ProjectReport`. That is a few git runs, so the reports are built when the page is shown and the root changed or a snapshot came since (`FProjectStale`, set by `ApplySnapshot`), and on every snapshot while the page shows, as the Commands page is reloaded. The page is a place Back and Forward return to (`pkProject`, back-forward.md) and View > Project is in the command palette as every menu item is.
- The colors are the Commands page's with a warning color between the ok and the error (`SetColors`, the two theme branches in `ApplyTheme`), and the card color for the checks.
