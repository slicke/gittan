# The Project page

Read this when touching `gittan.projectpage`, `umain.project.inc`, the Project row of the sidebar, View > Project, the kinds' chip and list, a section's buttons, or Add to .gitignore on a check. What the sections hold is each driver's (project-kinds.md); the Commands page whose output panel a button's command runs in is repo-commands.md.

- The page shows what the repository is as a project: the seventh row of the sidebar (`navProject`, after Pull Requests, which hides without a forge; `niProject`, a box seen from above a corner) and View > Project (Cmd+Option+7, Ctrl+Shift+7 elsewhere; `MenuProjectClick`). `TGittanProjectPage` (`gittan.projectpage.pp`) is painted like the Commands page in the same scroll box (`FView = gvProject`; `ShowProject` in `umain.project.inc`): the repository's name and root, then one section per kind (`TGittanProjectSection`, built by the kind's driver). The page knows no kind: it paints any block a driver gives it (project-kinds.md, the page's model). A section's heading is its name, its detail and its state at the right end in the state's color; a block's title a subheading. Facts are a column of dim labels as wide as the widest (within `MaxColShare` of the width), the value after it and a further cell after that. A table's columns are each as wide as their widest cell within `MaxColShare`, the widest giving way while they do not fit, the headers dimmed over a divider, a heading row a subheading, the last column at the right end when the block asks (`RightLast`). A cell is painted in its style; one with a `Url` is a link (underlined in the link color under the mouse; `OnOpenUrl`, `OpenURL`); a button (`psButton`) a pill in the card color with its text in the link color, filled with the link color under the mouse, its command as its hint (`OnRunCommand`); any text cut to its width has the whole as its hint, and a cell's `Hint` is its tooltip. The checks are a card: a disc in the warning color, the text wrapped, and Add to .gitignore at the right when the check has a pattern (`OnIgnore`). With no kind the page says what it looks for and that the chip picks one.
- The chip at the right of the title line names the kinds shown, "Found: Lazarus" in the text color when the files told them, "Picked: Lazarus, Go" in the link color when the user picked them, "No kind" for none, with a chevron (`PaintKindsChip`; its hint says what it is for). A click raises `OnPickKinds` with its rectangle, and the frame drops `FKindsPopup` (a `TGittanPopupList`, colored with the other lists in `ApplyTheme`) under it: Automatic, checked when nothing is picked, with the kinds the files tell as its detail (`DetectProjects`), then under "Kinds of project" every driver, the ones shown checked, each with the file that identifies it here as its detail. Automatic forgets the pick (`SetProjectKinds` with ''); a kind is taken in or out of the kinds shown, which are then kept as picked, "none" when it was the last (`KindsPopupPick`). The settings keep it per root in `projectKinds` in state.json, the root as the key, saved at once; `LoadRepoCommands` passes it to `DiscoverRepoCommands`, so the Commands page follows too, and the page is built again. A kind picked with no file of its own gets the standard section, which says the file is missing.
- A button runs its command as a command of the Commands page (`ProjectPageRun`, given the section's kind by the page): one the Commands page lists for that kind with the same line runs as that one through `RunRepoCommand`, so its tile shows the run and `confirm` asks; any other button runs a `TGittanRepoCommand` of `csProject` with the button's name, line and kind through `RunCommandRecord`, the part of `RunRepoCommand` after its trust check: in the job, the Commands page shown with its output panel, one at a time. A driver's command comes from the repository's own files as a script of package.json does, so it needs no trust.
- Add to .gitignore (`ProjectPageIgnore`) writes the pattern to the root's .gitignore as the file menu's item does (`AddIgnorePattern`) and takes the tracked files the pattern covers out of the index (`TrackedFiles`, then `RemovePaths` with keep, git rm --cached: the files stay on disk), since an ignored file git tracks is still tracked and the check would stay: a pattern ending in "/" covers the paths under that folder at any depth, "*.ext" the paths with that extension, any other the check's own path. The status bar says what was added and what stopped being tracked; the checks are built again with the snapshot the reload brings.
- `LoadProject` makes a `TGittanGitProjectContext` of the root (the newest tag reachable from HEAD, the tracked files; the files and submodules at the tag as a driver asks) and hands `ProjectSections(FRepoProjects, Context)` to the page with the kinds' names for the chip. That is a few git runs, so the sections are built when the page is shown and the root changed or a snapshot came since (`FProjectStale`, set by `ApplySnapshot`), after a snapshot while the page shows (`ApplySnapshot` queues `ReloadProjectAsync` once, `FProjectReloadQueued`, so the snapshot is drawn first and several in a row load once, and only if the page still shows and is stale), and after a pick. The page is a place Back and Forward return to (`pkProject`, back-forward.md) and View > Project is in the command palette as every menu item is.
- The colors are the Commands page's with a warning color between the ok and the error (`SetColors`, the two theme branches in `ApplyTheme`), and the card color for the checks, the buttons and the chip; the chip under the mouse takes the hover fill.
