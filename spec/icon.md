# Application icon

Read this when touching the artwork, `make icons`, the .ico/.icns/PNGs, how the macOS bundle gets its icon, the dialogs' icon or the welcome view's wordmark (`make wordmark`).

- The artwork comes finished (since 2026-11-05 a flat window on a dark tile, #141A26 with a 54/240 corner: a title bar with three dots, a grey line, a red line with a minus on a red band, a green one with a plus on a green band, a grey line; the designer's colors are red #FF4B58 and green #2BE070), drawn as SVG on a 256 grid and exported to PNG by its designer (the icon package, `gittan-ikonpaket`); nothing in the build draws or sizes it. `icons/gittan-linux.svg` is the package's `gittan-icon.svg` (48 pixels and up) and `icons/gittan-linux-small.svg` its `gittan-icon-small.svg` (a simpler drawing for 16 to 32: no dots or grey lines, the bands filling the window); `icons/png/gittan-<n>.png` at 16, 22, 24, 32, 48, 64, 128, 256 and 512 for Windows and Linux are the designer's exports, committed as they came (the package also has 96 and 1024, and an .ico, which are not used). `icons/gittan-mac.svg` is the macOS icon made here from `gittan-linux.svg`: its tile on Apple's 824/1024 grid (100 to 924, the corner 185.4) with a drop shadow, the drawing scaled by 824/240 onto it; its export `icons/gittan-mac.png` (1024 pixels) is what `make icons` packs. `make icons` runs `tools/makeicons.swift` (macOS only: CoreGraphics and `iconutil`), which packs them: `icons/Gittan.icns` from `gittan-mac.png` scaled to each size, `Gittan.ico` from the PNGs of 16 to 256 as they are (it refuses one of the wrong size). macOS 26 and later draw an .icns that is not their own shape on a grey tile of their own, which showed in Cmd-Tab; for them `icons/Gittan.icon` is an Icon Composer document, the tile's color (#141A26) as its solid fill and the mark as one layer (`Assets/mark.png`, Chrome's export of `icons/gittan-mark.svg`: the drawing of `gittan-linux.svg` without its tile, scaled by 1024/240 so the tile's 240 units fill the canvas: Icon Composer's canvas is the tile), which the system shapes, shadows and glazes itself; `make icons` also compiles it with Xcode's `actool` (`ACTOOL`: `/Applications/Xcode.app`'s, else the one `xcrun --find actool` names, as for an Xcode installed elsewhere; it needs an absolute path) into `icons/Assets.car`. A new artwork replaces those files and runs `make icons`. The exports made here are Chrome's: headless, a page with the SVG as an `<img>` of the size, `--default-background-color=00000000 --force-device-scale-factor=1 --window-size=<w>,<h>`. Commit the generated files; other platforms only consume them. The Linux release copies `icons/png/gittan-256.png` beside the binary as `gittan.png`.
- `Gittan.ico` beside `Gittan.lpi` is the project icon (`<Icon Value="0"/>` in the .lpi means it is set); Lazarus compiles it into the executable's resources, which the LCL uses for the window and taskbar icon on Windows and Linux. Under Wayland that icon is not used: the compositor (KWin, Mutter) takes a window's icon from the .desktop file named after its app_id and shows a generic Wayland icon without one (seen in KDE's task bar on Fedora). GTK takes the app_id from the program name, so `Gittan.lpr` sets it with `g_set_prgname('app.gittan.Gittan')` (behind `LCLGtk3`), and `make desktop` writes `app.gittan.Gittan.desktop` into `$XDG_DATA_HOME/applications` (`~/.local/share` by default), its `Exec` this checkout's `Gittan` (the folder from the shell's `pwd`, escaped as a quoted argument of the desktop file and then for sed, so a quote, a `$` or a `%` in the path stays in it), and copies `icons/png/gittan-<n>.png` into the user's hicolor theme as `app.gittan.Gittan.png`. The desktop file is `dist/linux/app.gittan.Gittan.desktop` (with the AppStream `app.gittan.Gittan.metainfo.xml` beside it); `make desktop` rewrites its `Exec`. `make packages` (fpm, and rpmbuild for the .rpm) stages the release build as it installs, `/usr/bin/gittan`, the lexers in `/usr/share/gittan/lexlib` (`gittan.lexers` looks in `../share/gittan/lexlib` from the executable), the desktop file, the metainfo and the icons in `/usr/share/icons/hicolor`, and packs a .deb and an .rpm into `pkg/` (each depending on git 2.30 or later, `git >= 1:2.30` for Debian's epoch), which CI publishes as `Gittan-linux-amd64.deb` and `Gittan-linux-x86_64.rpm` beside the tar.gz. The desktop file's `Exec` is `/usr/bin/gittan`, not `gittan`, since Install CLI Command's script in `~/.local/bin/gittan` comes first on PATH and starts the executable it was installed from. Tried on Fedora 44 under KDE Plasma (Wayland): the task bar shows the icon, from `make desktop` and from the installed .rpm.
- Lazarus creates `Gittan.app` without an icon, so the Darwin build targets in the Makefile copy `icons/Gittan.icns` and `icons/Assets.car` into `Contents/Resources` and add `CFBundleIconFile` and `CFBundleIconName` (Gittan, the .car's icon) to `Info.plist` after lazbuild. The `Info.plist` lazbuild writes into a new bundle has the project title as `CFBundleName` with a bare `&`, which PlistBuddy refuses to read (so CI, which always starts without a bundle, shipped no icon); the targets escape it, set `CFBundleName` to Gittan and check the result with `plutil -lint`. A bundle built from the Lazarus IDE lacks the icon until the next `make`. Finder caches icons; `touch Gittan.app` or a relaunch of Finder refreshes it.
- The dialogs' icon is the mark alone, without the application icon's tile: `icons/gittan-dialog.svg` (the window of `gittan-linux.svg`, its viewBox a square around it, 32 32 192 192, so the mark fills its box as a system icon does), rendered with Chrome headless with a transparent background to `icons/dialog/gittan-dialog-48.png`, `-96.png` and `-144.png`. `make dialogicon` turns them into byte arrays in `src/ui/gittan.dialogicon.inc` (kept in git, so a build needs neither the rule nor od and awk), which `gittan.dialogicon.pp` reads with `DialogIcon`, the PNG for the size in device pixels, read once. Gittan's dialogs (`gittan.askdlg`) draw it for a question, a note or an input, and the notice (`gittan.notice`) over its title; About keeps the application icon.
- The name with the icon, the lockup, comes finished too: the icon beside `gittan` in Manrope ExtraBold as outlines (`git` in the text color, `tan` in green on a green tile) over the tagline `Git Tree Analyzer & Navigator` (the initials of Git, Tree, Analyzer and Navigator in the text color, the rest grey), for a dark and a light background. The welcome view shows it: `icons/gittan-wordmark-dark.svg` and `-light.svg` are the package's `gittan-wordmark-dark.svg` and `-light.svg` as they came but for the viewBox, cropped to the drawing (25 25 950 310). The view does not draw them as SVG: Chrome exports them at 1045 by 341 to `icons/wordmark/gittan-wordmark-dark.png` and `-light.png`, and `make wordmark` turns those into byte arrays in `src/ui/gittan.wordmark.inc` (stopping on a PNG missing or empty, the include written beside and moved in place at the end, as `make dialogicon` does), which `gittan.welcome` resamples to the width it draws. The website's footer logo (`assets/logo-dark.svg`, `assets/logo-light.svg` on gh-pages) is the same two SVGs; its favicon and icons are `icons/png/gittan-32`, `-64` and `-256`.
