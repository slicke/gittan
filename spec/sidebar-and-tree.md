# Summary, sidebar, popup lists and the file tree

Read this when touching `gittan.summary`, `gittan.sidenav`, `gittan.repopage`, `gittan.popuplist`, the file tree and its icons.

- The space right of the tree is shared by the editor and the summary; `ShowEditor` and `ShowSummary` in `umain.pp` switch between them. `gittan.summary.pp` holds `TGittanSummary`, a self-painted control (repository name, branch, totals, then one row per file with its badge from `TreeImages`, the counts and a bar comparing the change sizes, or in their place the row's text from `SetRepository`'s `ATexts` (a changed submodule's "b0193be → 2844a79", `SubmoduleMoveText`), its row left out of the bars' scale, and after the file name the row's pill from `AActions`, outlined, its text in the link color under the mouse (`FActionRects`, `ActionAt`, `OnRowAction`): a conflicted file has Resolve (`rsResolvePill`), which `SummaryRowAction` in `umain.conflicts.inc` turns into the file shown at its first conflict (`FConflictRows[0]`; a file without markers shows its header's pills); when there are no rows, the clean state in place of the totals line: a large green check (`DrawCheck`), "Working tree clean" at `CleanFontSize` and under it how far the branch is from its upstream (`PaintSync`), "↑ 2 not pushed" in the link color, "↓ 1 not pulled", or "up to date with upstream"; with nothing below it (no commit waiting to be pushed, so also none without an upstream, and no pull request conversation, `CentersClean`) the header keeps only the title and the check, the text and the sync line stand larger in the middle of the control instead (`PaintCleanCentered`), as the empty view's icon does; otherwise, while some commits are not pushed (`ShowsCommits`), under a "Recent commits" heading where the rows would start, the newest ten commits of HEAD: a dot on a line down the icon column, filled in the link color when the commit is not pushed, the subject cut to fit, the author and age (`ReviewAge`; the author goes first, then the age, when room is short) and the short id at the right; a click on one fires `OnSelectCommit`, which `SummarySelectCommit` in `umain.actions.inc` turns into `ShowBlameCommit`, as a pick from the status bar's sync list. While a commit is shown against its parent (`BlameShown`: the base is `FBlameRange`, from the commit graph, the blame band or these rows), a card under the header names it (`SetCommit`, `LayoutCard`, `PaintCard`, laid out as a note's card with a stripe in the link color): the subject in bold, wrapped short of a "Back to Working Tree" link at the right of its first line (`OnBackClick`, `SummaryBackClick`: `SetBase('')`), at most `SubjectMaxLines` (3) lines; the author, age and short id dimmed; and the body wrapped as a note's text (`WrapText`, shared with the notes), blank lines kept but not doubled, at most `NoteMaxLines`. `ShowBlameCommit` reads them with `TGittanRepo.CommitDetails` (`git log -1` with the fields split at unit separators and the body last; tested in `TestCommitRange`) into `FBlameCommit` and `FBlameBody`. The base label is then a chip in the summary and the status bar too, dropping Back to Working Tree and Copy Commit ID (`BaseClick`, `FBaseBackIndex`, `FBaseCopyIndex`). The commits come from `TGittanRepo.RecentCommits` (`git log -n 10` with author and commit time, marked `Unpushed` from `rev-list @{upstream}..HEAD` cut at the same count; tested), which `Snapshot` calls into `Recent` only when the tree is clean; `ApplySnapshot` hands them to `SetCommits` with the ahead and behind counts) that sits in a `TScrollBox` created in `FormCreate` for native scrolling. Its `Selected` path marks the row of the file the editor showed last (`ShowChanges` and `ShowSubmodule` set it, the other views clear it). `SetRepository` aligns it `alTop` with its height from the content, `SetMessage` (the hint before a repository is open: the application icon, the message and the menu path with its shortcut) aligns it `alClient`; the scroll box's `OnResize` keeps its `MinHeight` at the box height so its background fills the box. A click on a row selects the file in the tree through `SummarySelectFile`, which runs the usual selection handler; a submodule's row shows `ShowSubmodule` directly, also when the filter hides its node. `ShowSummary` clears the tree selection so picking the same file again fires it. The View menu has Summary (Cmd+1) and Repository Diff (Cmd+2); `ShowRepoDiff` shows `git diff HEAD` (or `git diff` before the first commit) in the editor under the Diff lexer with its `+`/`-` lines colored.
- The sidebar starts with three rows (`TGittanSideNav`, `gittan.sidenav.pp`, self-painted in the sidebar's shade, under the filter field or at the top when the toolbar holds the field; `Large`, so the rows are 36 high with an 18-pixel icon drawn in a two-pixel line and 15-point text, as a music app's, while the settings dialog keeps the small rows that are as high as the section headers) that open the pages of a repository, as a music app's sidebar has Home and Explore over the library: Home shows the summary (what the repository's name in the status bar and View > Summary show), Graph toggles the commit graph (`navGraph`, as View > Commit Graph does) and Repository a page about the repository itself, `TGittanRepoPage` (`gittan.repopage.pp`, painted like the summary in the same scroll box, `FView = gvRepoInfo`, View > Repository Info, Cmd+Shift+I). Its header has the name with the branch after it (the branch icon, as the summary's header) and what the branch tracks, the path under them; then a row of tiles (`PaintTiles`, in `SetCardColor`'s fill, as many in a row as fit at `TileMinWidth`, the rows as even as they can be: the name dimmed, the count large, a detail dimmed), the remotes (`PaintRemote`: a globe for a web address, else a folder, the name in bold, the URL, and a push URL of its own dimmed under it) and the contributors (`PaintContributors`: a disc with the initials and a bar in the commit graph's lane colors, `SetLaneColors` from `HistoryColor(…, htSwatch)` as the graph has them, the count and the share of all commits at the right). The tiles and the contributors' rows lead on, filled with the hover color under the mouse (`OnOpenTarget`, `RepoPageOpenTarget` in `umain.repopage.inc`, the tile's or row's screen rectangle passed for a list to drop from): Commits opens the commit graph, Branches and Tags drop their lists (`ShowBranchList`, `ShowTagList`) from the tile, Files opens the tree of HEAD in the repository browser (`BrowseCommit`), Submodules shows the submodule's page, or with more than one drops `FSubListPopup` to pick one (`FSubListRows` maps its rows, the header counting among them), and an author's row opens the commit graph filtered to `author:<name>`; Commits, Tags and Files lead nowhere before the first commit, Size never. The page lists what `GatherRepoInfo` in `gittan.repoinfo.pp` (no LCL, tested in `tests/testrepoinfo.pp`) reads with git: the branch and its upstream, the commit count with the first commit's date (`log --max-parents=0`) and the latest one's age, local and remote branches, tags with the newest three (`for-each-ref --sort=-creatordate`), tracked files (`ls-files`), submodules (`.gitmodules`), the size of the objects (`count-objects -v`, loose plus packed, `FormatKiB`), the remotes (`remote -v`, a hosting URL shown as a link through `RemoteWebUrl`: https, scp-like and ssh:// forms become a browser address, a path none) and the eight authors with the most commits (`shortlog -sn`, with a bar against the largest count; `ParseShortlog` merges the spellings of one name that differ only in case or in how their letters are composed, as git keeps "Björn" with a precomposed ö apart from one with a combining mark, by `NameKey`). `TGittanRepoInfoJob` runs the gathering off the main thread (`umain.repopage.inc`: `StartRepoInfoJob`, one at a time, a start meanwhile is run after; the done job goes to the zombie list as a blame job does) each time the page is shown and after each refresh while it is shown, the page keeping the facts read before. The selected row follows the view (`navHome`, `navRepository`, none in the editor) and never leads it: a click calls the menu actions. Every view sets its row through `SetNavRow`, which keeps it in `FNavViewRow` and selects it, or the Graph row while the commit graph is open (`ShowCommitGraph` selects `navGraph` after the popup; `GraphClosed`, the graph's `OnClose`, puts the view's row back). The graph's user input hook closes it on a press outside it, which would reopen it on the Graph row's release, so the graph's `Keeper` is the sidebar's rows, whose presses leave it open; `SideNavPick` closes it itself before showing a page. Under the three, a little apart and at the small size (`AddRow`'s `ASmall`; `RowTop`, `RowHeightOf` and `RowsHeight` add the rows up, since they differ), two rows that are never selected: Recent drops `FRecentPopup` from the row (`ShowRecentList`, anchored at `RowScreenRect`: the recent repositories as File > Open Recent names them with `ShortPath`, the open one checked, "No recent repositories" as a header when there are none, and Open Repository... last; `RecentPopupPick` opens the pick) and Settings opens the settings dialog. Under the rows the control paints its `Heading`, "Files", a dim bold title with a page icon, set in as the section headers set their chevron and title, over a line as the headings of the repository page, naming what the sidebar lists below as the music app writes Library over its playlists. The Home row holds, at its right end, the button that folds the other rows away (`ShowToggle` with the hints "Hide navigation" and "Show navigation"; `Collapsed`, `OnCollapse`; `ToggleRect`, `DrawToggle`), as the music app's sidebar folds at the button beside its name: a window with its sidebar and an arrow into it, which points out again while they are folded, when Home alone is left over the Files heading and the files (`RowsHeight` and `RowAt` count the first row only then). The state is `NavOpen` in the settings (`Nav` in `[Window]`, on by default), applied in `ApplySettings` and saved in `FormClose` as the sections' states are. While git reports no change (`FTreeClean`, set by `FillFileTree`, a filter that hides every file not counting, cleared by `ShowWelcome`) the empty tree shows the summary's mark for a clean tree in gray, a large disc with a check, and "No changes" under it, in its middle (`FileTreeAdvancedCustomDraw`, the tree's post-paint stage).
- `gittan.popuplist.pp` holds `TGittanPopupList`, a panel that drops down from whatever was clicked and offers a choice from a list: items added with `Add` (caption, a dimmed detail, `Checked` for the current choice, drawn with a check mark) and `AddHeader` for group names, a native `TEdit` filter on top when there are more than `FilterOver` pickable items, the rows self-painted in a `TScrollBox` for native scrolling. `Popup` takes the anchor rectangle in screen coordinates, places the panel under it (above when there is more room there, within the parent), focuses the field or the rows, and `OnPick` reports the index `Add` gave; Escape, a click outside (seen through `Application.AddOnUserInputHandler`, which Cocoa calls with the control under the mouse but a stale message, so the mouse buttons are asked through `GetKeyState`) or the application going to the background closes it, `OnClose` follows every hide. It is a child of the form, not a window of its own, so it draws over the editor and the summary alike. The summary draws the branch as the status bar does, a branch icon (`DrawStatusIcon` with `HintBranch`) before the name in the text color, as a chip with a dimmed chevron while `OnBranchClick` is set; `SummaryBranchClick` in `umain.actions.inc` fills `FBranchPopup` from `TGittanRepo.Branches` (local branches, then remote-tracking ones without a local branch, under headers; a local branch whose upstream is deleted on the remote has "deleted on remote" as its detail: `GoneBranches` gives the ones git already sees as `[gone]` in `%(upstream:track)`, `FGoneBranches` the ones the remotes themselves report, since Gittan never fetches and a branch GitHub deleted after a merge keeps its remote-tracking ref until a `fetch --prune`; `TGittanPullRequestJob` fills it in its thread through `GoneUpstreamsIn` in `gittan.git.pp` (`ls-remote --heads` once per remote a branch tracks, a remote that cannot be reached counting nothing as gone), and for the current branch the summary's sync line says "✕ upstream deleted on remote" in red in place of the counts, `TGittanSummary.SetUpstreamGone`) and `BranchPopupPick` runs `SwitchBranch`: `TGittanRepo.Switch` (`git switch`), with the watcher stopped meanwhile and `RefreshRepository` after; a switch that local changes block (`SwitchBlockedFiles` reads the files git lists after "would be overwritten by", local changes or untracked files the branch has) asks with those files listed, up to ten: Stash and Switch (`Stash`, `stash push -u` with a message naming the branch; the status bar says the changes are in the stash), Bring Changes Along (`Switch(..., True)`, `switch --merge`, which may leave files in conflict) or Cancel; any other refusal shows git's whole message in a dialog. A single line in the summary's notice, cut at the colon before the files, read as nothing happening. Tested in `tests/testgit.pp` (`TestSwitchBlocked`). `FitHeight` keeps the summary exactly as high as its scroll box when its content is shorter (a `MinHeight` constraint alone left it at an old, larger height after the box shrank, and the box scrolled on a click).
- The `TTreeView` on the left lists only the changed files, taken from the same `git status --porcelain` output through `ChangedPaths` (untracked files included, a rename shown under its new path), folders first, every folder expanded (`FullExpand` in `FillFileTree`; `RefreshRepository` closes again the folders the user had closed). It has no border and no tree lines (`BorderStyle = bsNone`, no `tvoShowLines`/`tvoShowRoot`), so on the widgetsets that draw them it looks like the native tree on macOS. A file node has `Data` set; folders and submodules have `Data = nil`. Selecting a submodule's node (`SubmoduleAt` finds it in `FSubmodules`) shows `ShowSubmodule`, and its hint says how it moved (`rsHintSubmodule`).
- `ChangedPaths` also condenses each file's "XY" status into a `TGittanChangeKind` (`ChangeKind`), stored in the list's `Objects`. The tree shows it as an icon from `TreeImages`: `gittan.icons.pp` draws the icons at startup with BGRABitmap (a direct dependency of the project, as it already is of ATSynEdit), a folder, the badges per kind with git's status letter (M, A, D, R, U for untracked, ! for a conflict; untracked in gray, added in green) in their three fills, and the folder with a dot in each kind's color (`FolderIcon`), at both 16 and 32 pixels through `AddMultipleResolutions` so the tree picks the sharp one on a Retina screen. There are no image files to ship. A file in the tree says what its badge means as a hint after `Application.HintPause` (`StatHint`: the kind, then " · staged" or " · partly staged"): `FileTreeMouseMove` finds the row's stat and starts `FTreeHintTimer`, which sets the tree's `Hint` and calls `Application.ActivateHint`, as the editor's hover does, since the LCL's hint does not follow a hint that changes within one control on Cocoa; moving to another row or out of the tree (`FileTreeMouseLeave`) cancels it. A folder node carries the dot of the most severe change inside it (`WorseKind`: conflict, deleted, modified, renamed, added, untracked); `FillFileTree` walks up from each file and reads the folder's current kind back from its `ImageIndex` with `FolderIconKind`.
- The tree from `umain.lfm` is moved at startup into `FTreePanel`, aligned left in its place, under a native `TEdit` filter field (`SetupTreeFilter`; the splitter sizes the panel and `TreeWidth` in the settings is the panel's width). `ColorSidebar` (from `ApplyTheme`) gives the panel, its three trees and the form the gutter's shade the section headers use (37,37,38 dark, 246,246,246 light), so the sidebar is one block, splitter included, and the editor panel the editor's background.
