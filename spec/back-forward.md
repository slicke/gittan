# Back and Forward

Read this when touching `gittan.navhistory`, `umain.nav.inc`, Go > Back and Go > Forward, or a new view or page that should count as a place to go back to.

- Go > Back (Cmd+[, Alt+Left elsewhere; `FBackItem`) and Go > Forward (Cmd+], Alt+Right elsewhere; `FForwardItem`) step through the places a frame has shown, as a browser does through its pages. Each frame keeps its own (`FNavHistory`), forgotten when another repository is opened in it (`NavClear` from `OpenRepository`). The items are enabled only while there is somewhere to go (`NavUpdateItems`), so the command palette lists them only then and the keys do nothing otherwise. Two chevrons in the title bar do the same, on macOS right of the traffic lights, first in the tab strip, on Windows and GTK 3 after the own title bar's menu button: `NavUpdateItems` tells the window (`TRepoWindow.NavChanged`), which sets them from the frame's `CanGoBack` and `CanGoForward` and passes a click to its `GoBack` or `GoForward` (window-chrome.md). Cmd+[ and Cmd+] are free in ATSynEdit's macOS keymap, and Alt+Left and Alt+Right in the others.
- A place is a `TGittanPlace` (`gittan.navhistory.pp`, no LCL, tested in `tests/testnavhistory.pp`): its kind (the summary, a changed file in the change view or the image, translation or binary view, the repository diff, a file open in the editor, a file of a commit from the Files page, the Files page, the Repository, Commands and Pull Requests pages), its path, the comparison it was shown against (`Base`, `WholeTree`, and `Commit` when the comparison is a commit picked to be compared with its parent, `FBlameRange`) for the summary, a changed file and the repository diff, the commit and its name for the Files page and its files, and in an editor the caret's row and column and the first row in view. `SamePlace` compares everything but the rows; `SamePlaceAndRow` the row too. `TGittanNavHistory` keeps a back list and a forward list of at most 100 places each, the oldest dropped first: `Visit` puts the place being left on the back list (not twice in a row at the same row) and empties the forward list; `Back` and `Forward` hand out the place to go to and put the one being left on the other list.
- The frame reads what it shows as a place (`NavCurrent`, `umain.nav.inc`) whenever the application is idle (`NavIdle`, an `Application.AddOnIdleHandler` taken off in `Destroy`, acting only for the frame shown), so every way of getting somewhere counts without its handler knowing: the tree, the summary, F8, Go to Definition into another file, a commit picked in the graph, Compare With, a page from the sidebar. `NavSync` compares it with the place noted (`FNavPlace`): another place puts the noted one on the back list and is noted in its stead; the same place has its rows brought up to date, so going back lands where the caret was left. A jump within a file notes the place before it: `JumpToDefinition` (a definition, a symbol from the symbol bar, a caller) calls `NavMark`, which syncs first and, when the file was only just shown (a definition in another file), leaves it at that, since the place before it went on the list then. The code history, a submodule, the welcome view and a file opened from disk outside the tree are no places: while they are shown nothing is noted, and the place before them stays the one to go back to. The idle check runs only when the message queue is empty, so the steps of one navigation (a summary shown on the way to a file) are not noted.
- `NavStep` syncs, then takes places off the list until one can be shown again (`NavRestore`): the comparison first, for the kinds it matters to (`ShowBlameCommit` for a commit, else `SetBase`; a base git cannot resolve any more fails the place), then the place: the summary (`ShowSummary`), a changed file (`SummarySelectFile`, or `ShowChanges` when the tree's filter hides it; a file no longer changed fails it), the repository diff, a file (`OpenFile`, the tree's selection dropped as `ShowRepoFile` does; a file gone fails it), a file of a commit (`ShowFilesAt` with the commit's subject from `CommitDetails`, then `ShowBlob`), the Files page (`ShowFiles` for HEAD's, `BrowseCommit` for a commit's) or a page. `NavRestoreRow` puts the caret back at its row and column and the first row in view, clamped to the text, after `UpdateWrapInfo` and with `LineTopTodo` cleared, since the editor may only just have been shown and the line top it kept from that resize would win at its first paint (as for the symbol bar's pick). `FNavBusy` keeps the idle check out meanwhile, since loading a file may pump messages. A place that cannot be shown is passed over; when none is left the status bar says "That place is no longer there." and what is shown is noted afresh, and the place it left on the other list goes when it is the one shown (`TGittanNavHistory.Settled`), so the other way does not step to what is on screen. The commit graph is closed first.
