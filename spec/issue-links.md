# Issue references in commit messages

Read this when touching `gittan.issuelinks`, `umain.issues.inc`, File > Issue Tracker..., the bugtraq config keys, or the links in the summary's commit card.

- A repository names its issue tracker in git config with the bugtraq keys that several git clients share, so a setup made in one of them holds in Gittan too: `bugtraq.url`, the address of an issue with `%BUGID%` where its id goes (`IssueIdMarker`; appended when the marker is missing), and `bugtraq.logregex`, how a message refers to one: a regular expression whose first group (or whole match, without one) is the id, or two on two lines, the first finding each reference in the message ("Fixes #12 and #13") and the second the ids within a reference. `gittan.issuelinks.pp` (no LCL, tested in `tests/testissuelinks.pp`) holds `TGittanIssueTracker` (`Url`, `LogRegex`; `IssueTrackerEmpty` is no expression), `ParseIssueTrackerConfig` (the output of `git config -z --get-regexp ^bugtraq\.`, a key, a line break and the value per NUL-ended entry; `-z` since the expression may hold two lines), `FindIssueLinks` (the references in a text in order, as `TGittanIssueLink`: a 1-based byte start, a length and the id, found with FPC's `TRegExpr`; an expression that cannot be read marks nothing, and an empty match never moves on) and `IssueUrl` (the address of an id). `DefaultIssueRegex` (`#(\d+)`) is how a forge's issues are referred to without a tracker.
- The snapshot reads the tracker (`IssueTrackerIn` in `gittan.git.pp`, in the watcher's thread as `ResolvedRemoteUrlsIn` is) into `IssueTracker`, and `ApplySnapshot` keeps it in `FIssueTracker` and calls `UpdateIssueTracker` (`umain.issues.inc`), which hands the summary (`TGittanSummary.IssueTracker`, a setter that repaints only on a change) the config's tracker, or, when it names no expression and a forge is assigned, one with `DefaultIssueRegex` and no address. The card marks the references in the subject, the body and the note (sidebar-and-tree.md) and raises `OnIssueClick` with the id: `SummaryIssueClick` opens `IssueUrl` in the browser, else on the forge (`OpenOnForge` with `IssueTarget`, which wants a number), else a status note says no address is set.
- File > Issue Tracker... (`FIssueTrackerItem`, enabled with Remotes... in `UpdateRemoteItems`; `MenuIssueTrackerClick`) asks with `AskInput` for the address, the expression and, optionally, the expression for the ids within a reference (the second line of `bugtraq.logregex`), filled from the tracker read; OK writes them with `TGittanRepo.SetIssueTracker` (`git config --local --end-of-options` per key, since an expression may start with a dash; an empty value unsets its key, which is no failure when the key is not there; tested in `TestIssueTracker`) and refreshes, so everything left empty takes the tracker out.
