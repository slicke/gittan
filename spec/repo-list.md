# Repository list

Read this when touching `gittan.repolist`, `umain.repolist.inc`, the welcome view's list (`gittan.welcome`), File > Repository List or File > Add to Repository List.

- The repository list is the repositories the user keeps at hand, in folders of their own naming (folders may hold folders) and in the order they put them; unlike the recent repositories nothing comes in by itself. `gittan.repolist.pp` (no LCL, tested in `tests/testrepolist.pp`) holds it as a tree of `TGittanRepoEntry` (a folder with its entries and whether it is `Collapsed`, or a repository with its `Path` and an own `Name`, '' for its folder's; `Caption` is what is shown) under the never shown `Root` of a `TGittanRepoList`. `AddRepo` refuses a path the list has anywhere (`Find`; paths go through `RepoListPath`: expanded, no trailing delimiter), `Move` puts an entry before the entry that is at an index now (one less when it comes out ahead of it in the same folder) and refuses a folder put inside itself, `Remove` frees a folder with what it holds, and `Rows` are the rows shown with their depth, nothing inside a collapsed folder.
- The list lives in `repositories.json` in `ConfigDir`, beside gittan.ini (`{"items": [{"folder": ..., "collapsed": true, "items": [...]}, {"path": ..., "name": ...}]}`), written whole after every change through a temporary file renamed over it (`Save`), so it does not depend on Gittan closing normally as the ini does. A missing or unreadable file gives an empty list, and what can be read of a damaged one is kept. `App.RepoList` (`gittan.app`) is the one list, read as App is created; two Gittans running at once each write theirs, the last save winning.
- `FindRepositories` lists the repositories in a folder and the folders under it, `FindDepth` (3) deep, sorted by path, not looking into a repository, a hidden folder or a link; the folder alone when it is one. A repository is a folder with `.git` in it, a folder or a file (a worktree, a submodule).
- The welcome view shows the list between the buttons and the recent repositories (`SetRepoList`, `PaintList`): a dim heading "Repositories" with a + at its right over a divider, then a row per row of `Rows`, indented 20 px per depth: a folder's with a chevron (down while open), its name in bold and how many repositories it holds, a repository's as a recent one's (the name over the path, dimmed with "not found" when its folder is gone). An empty list shows a line that says to drag a recent repository there or use the +. A folder's row folds it on a click, a repository's opens it (`OnOpenRecent`). The view is placed as if every folder were open (`FoldedHeight`), so folding does not move the rows under the pointer.
- A row of the list, or a recent one, dragged more than `DragStart` px is dropped in the list (`ComputeDrop`): into a folder over the middle half of its row (the row outlined in the accent), before a row over its upper half, after it over its lower half (before the first entry of an open folder with entries), at the end under the last row; the line where it lands is drawn in the accent, indented to its depth. A recent repository the list has moves there; one it has not is added. A folder dropped inside itself is no drop (`crNoDrop`).
- The view measures its height before it paints (`Layout`, from `FitHeight`, `Resize` on a new width and every setter, on `MeasureCanvas`; `Render` measures or draws with the same code), since the summary box scrolls wrong under Cocoa when a child grows in its paint, which left it blank after a drag made the list taller.
- What the view changes itself (a fold, a drag) it tells with `OnListChanged`; a right-click on the list, on the + or on a recent row asks for the menu (`OnListMenu`). The frame (`umain.repolist.inc`) answers both: every change goes through `SaveRepoList`, which saves (an error banner when the file cannot be written) and calls `TRepoWindow.RepoListChanged`, which has every frame's welcome view read the rows again (`TRepoFrame.RepoListChanged`). The menu has Open, Rename... (a folder needs a name; a repository's empty name, or its folder's, is no own name) and Remove from List for a repository; Rename... and Remove Folder... for a folder (asked first when it holds repositories, which stay where they are); for a recent repository Add to Repository List (enabled while the list does not have it), Remove from Recent and Clear Recent, which `RecentChanged` (`umain.actions.inc`, also behind File > Open Recent > Clear) writes into the ini at once (`TGittanSettings.RemoveRecent`, `SaveRecent`, which writes the `[Recent]` section alone, tested in `TestSaveRecent`) and shows in every frame's Open Recent and welcome view; then New Folder..., Add Repository... (the folder dialog, the root of the repository the folder is in by `rev-parse --show-toplevel`) and Add Repositories in Folder... (`FindRepositories`, the ones found in a new folder named after the folder picked; nothing made when none is found or the list has them all). What it adds goes into the folder right-clicked, the folder of the repository right-clicked, else the top, and opens that folder.
- File > Repository List (`MenuRepoListClick`, so the command palette has it) calls `TRepoWindow.ShowRepoList`: the welcome view in the tab shown when it has no repository, else in another tab that has none, else in a new tab; the forge view is hidden first. File > Add to Repository List (`FAddListItem`) adds the repository open at the top, enabled while a repository is open that the list does not have (`UpdateRepoListItem`, after an open, in the welcome view and on every change of the list).
