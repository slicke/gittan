# Config section and editing repository files

Read this when touching `umain.repofiles.inc`, `gittan.repofiles`, the ignore menus or editing .gitignore and the like.

- The Config section (`umain.repofiles.inc`, titled "Config" since it lists the files that configure the repository, not its content; it was "Repository" before the sidebar got a Repository row) sits at the bottom of the tree panel: `FRepoPanel`, aligned `alBottom`, holds a `TGittanSectionHeader` (`gittan.sectionheader.pp`: a self-painted row with a chevron, a title, a dimmed detail and `OnToggle`, in the file header's palette from `ColorRepoHeader`) over `FRepoTree`, a second `TTreeView` with the first one's options and images. It lists the repository's own files whether or not they changed: `ListRepoFiles` in `gittan.repofiles.pp` (no LCL, tested in `tests/testrepofiles.pp`) gives the `RepoRootFiles` that exist (.gitignore, .gitattributes, .gitmodules, .mailmap, .editorconfig, in that order) and then every file under `.github`, sorted; `FillRepoFiles` (from `ApplySnapshot`, so the watcher keeps it current) builds the tree with the plain file icon `iconFile` from `gittan.icons.pp` and puts the count in the header's detail, and hides the panel when there is nothing. `LayoutRepoFiles` makes the panel the header alone while folded, else the header plus the rows in view up to half the tree panel (also on the panel's resize); the state is `RepoFilesOpen` in the settings. A click goes through `ShowRepoFile`, so a changed file is selected in the tree above with its diff and a plain one is opened as File > Open does; `FileTreeSelectionChanged` and `ShowSummary` clear the section's selection so only one tree keeps one. The file menu's "Add to .gitignore" and "Add to .git/info/exclude" submenus (`FIgnoreMenu`, `FExcludeMenu`, filled by `FillIgnoreMenus` from `FilePopupPopup`) offer `IgnorePatterns` for the file: the file anchored at the root, its extension as `*.ext`, and its folder; enabled for an untracked file only. `MenuIgnoreClick` writes the pattern with `AddIgnorePattern` (the file and its folder made when missing, a newline supplied before it when the file ends without one, a line already there left alone), says so in the status bar and runs `RefreshRepository`; the exclude file is `ExcludeFile` under `TGittanRepo.GitDir`, found once per `OpenRepository` into `FExcludePath` (`GitDir` runs git), and listed last in the section as one row, `ExcludeShown`, with `Data` 2 (the other files have 1), which `RepoTreeSelectionChanged` opens straight from `FExcludePath`.
- The files the section lists are the only ones the editor lets the user change (the editing section of `umain.repofiles.inc`). `OpenFile` asks `RepoFileName` (the exclude file, or a file under the root that `IsRepoFile` in `gittan.repofiles.pp` accepts) and calls `BeginEdit`, which lifts `ModeReadOnly`, notes the file's `FileAge` in `FEditStamp` and puts Revert and Save pills in the header; undo and redo are the editor's own Cmd+Z and Shift+Cmd+Z. The diff view of such a file (`ShowChanges`) gets an Edit pill that opens the file view, with the file selected in the section (`SelectRepoNode`) rather than the tree above, so a click there brings the diff back. `UpdateEditState`, from `Edit.OnChangeModified`, sets the header's dot, the pills and File > Save (Cmd+S, `FSaveItem`) from `Edit.Modified`. Everything that replaces the editor's text or leaves the view (`OpenFile`, `ShowText` for `Edit`, `ShowChanges`, `ShowSummary`, `OpenRepository`) first runs `FlushEdit`, a Save / Don't Save question with no way to stay, then `LeaveEdit`; `FormCloseQuery` asks with a Cancel too. `SaveEdit` writes with `TATSynEdit.SaveToFile` (the encoding and line ends the file was read with), notes it in the status bar and, from the pill or the menu, runs `RefreshRepository` so the tree shows the result at once. `RefreshRepository` keeps the section's selection across the rebuild and, in the file view, reloads a repository file that changed on disk while the editor holds it unchanged, or shows "changed on disk" in the header when an edit is in progress. `RevertEdit` asks, then loads the file again through `OpenFile` at the same scroll position. The editor's `OptCaretVirtual` is off (`SetupEditor`) so typing past a line's end does not pad it with spaces.
