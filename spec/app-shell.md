# Opening repositories, settings, the CLI command and updates

Read this when touching File > Open, `gittan.app`, `gittan.settings`, the settings dialog, `gittan.cli`, `gittan.update`, the window caption or `UpdateStatus`.

- File > Open Repository (Cmd+Shift+O) uses the `TSelectDirectoryDialog` on the form (a folder on the command line, `gittan <folder>`, a folder dropped on the window, or File > Open Recent opens one too), then `OpenRepository` in `umain.pp` fills the tree and the summary from `ChangeStats`. There is no toolbar: the summary's hint tells a first-time user what to do; the welcome view (`gittan.welcome.pp`, shown while no repository is open) has the wordmark at the top (no wider than the column), the icon beside the name and the tagline as gittan.app has them: `icons/wordmark/gittan-wordmark-dark.png` on a dark background, `-light.png` on a light one (icon.md), made into byte arrays in `src/ui/gittan.wordmark.inc` by `make wordmark` (the .inc is kept in git, so a build needs neither od nor awk), resampled to the screen's pixels (`LogoBitmap`, made again when the colors change; the title and the tagline as text if it cannot be read). Under it, Open Repository..., filled in the accent (`SetAccent`, the status bar's primary button's) with its key caps inside it at the right (left out when a narrow column stacks the buttons too narrow for the caption and the key caps both), Clone... and Init... in a row as wide as the column of the recent repositories, Open taking what the other two leave (under each other, each as wide as the column, when the row does not fit; `OnClone`, `OnInit`), then the dim line that a folder can be dropped, then the recent repositories, one with its folder gone dimmed with "not found" at the right of its name's line. While no repository is open the frame hides the sidebar and its splitter (`ShowSidebar`, from `ClearRepositoryViews` and at creation; shown again when one opens, in `OpenJobDone` and `ApplySnapshot`; the own title bar's shade then has no split), and the status bar has no transport buttons (`UpdateStatusTransport`). A folder that is not a repository, or a git failure, is shown in the empty view in the hint's place (`ShowError`), not in a dialog.
- `gittan.app.pp` holds `TGittanApp`, what every repository shares, one per process: the settings (read as it is created, which also sets the git to run, `SetGitExe`), the lexers (created there, loaded by the window, which takes `OnLoaded`), the application icon (`Icon`, MAINICON at every size, which the notice draws) and the check for a newer build. The window (`uwindow.pp`) creates it first in `FormCreate` (`CreateApp`) and frees it last in `FormDestroy` (`FreeApp`), after the frame; the code reaches it through `App` (`App.Settings`, `App.Lexers`). It is the first step towards several repositories open in one window, each in a frame of its own, with the app shared.
- The window holds a frame per open repository, behind tabs (`uwindow.pp`; the strip on macOS in `gittan.toolbar.pp`, the own title bar on Windows and GTK 3 in `gittan.owntitlebar.pp`, see window-chrome.md). File > New Tab (Cmd+T) and the strip's plus make an empty frame with the welcome view; File > Close Tab (Cmd+W), the cross and a middle click close one (`CloseFrame`, from the message loop: a frame with unsaved changes is shown and asks first, then saves what closing the window saves), showing the tab to its right, else its left; closing the last leaves an empty one. A tab whose frame had news while another was shown has a blue dot before its name until it is shown (`MarkNews`, `HasNews`, cleared by `Activated`): a banner, a failure's notice, a commit or remote job that ended, or a snapshot with another number of changed files, other commits behind or another HEAD; the first snapshot after an open is not news, so the tabs opened at start come up without. Next Tab and Previous Tab (in the Window menu on macOS, in Go elsewhere; Cmd+Shift+] and [, and Ctrl+Tab and Ctrl+Shift+Tab in the window's `FormKeyDown`) step round them. On macOS the menu bar ends with Window (Minimize, Cmd+M; Zoom, the green button's `zoom:` through `ZoomWindow` in `gittan.titlebar.pp`, since the LCL's `WindowState` does not tell a zoomed window apart; the tabs; Bring All to Front), and everywhere with Help (Gittan Website, Release Notes and Report an Issue, `GittanSite` and `GittanSource` from `gittan.settingsdlg`), where macOS adds its own search field, which searches the menus too. Cmd with a digit (Ctrl elsewhere, in the window's `FormKeyDown`, no menu item) shows that tab, 9 the last one, as in a web browser; the views those keys had (View > Summary to GitHub) take Cmd+Option with the digit on macOS, where Cmd+Shift+3 to 5 are the system's screen shots, and Ctrl+Shift elsewhere, where Ctrl+Alt is the repository commands' (`ViewKeys` in `umain.pp`). Cmd+0 stays Reset Zoom. Opening a repository (File > Open Repository, Open Recent, the welcome view, a dropped folder, the gittan command, clone, init, the GitHub page, a submodule) goes to `TRepoWindow.OpenRepository`: the tab that has it open or is opening it is shown, else the shown tab takes it while empty, else a new tab. The root is found with one git per call: a frame opening keeps the root the window gave it (`OpeningRoot`), so the frames are compared by name. An `AOnOpened` callback for a tab still opening waits until it has opened (`WhenOpened`, a list in the order asked); the callback is the asking frame's, and closing that frame drops it from the frame still opening (`DropCallbacksOf` from `CloseFrameAsync`), which also checks again after its save question that the frame is still there and runs no second close of a frame whose question is open (`FClosing`). The settings dialog's OK reaches every tab (`TRepoWindow.SettingsChanged`, the shown one last): the editors' font, syntax theme and tab size, the agent, and after a change of git, gh or the GitHub switch the forge and a refresh (`TRepoFrame.SettingsChanged`); what the settings keep is set once. Closing the window shows a tab with unsaved changes before it asks (`NeedsSave`). The repositories in the tabs and the shown one are kept in the settings (`Tabs`, `ActiveTab`, section `Tabs`; a tab still opening counts by its `OpeningRoot`, one without a repository is left out) and open again at the next start (`OpenAtStartAsync`), with a folder on the command line in a tab of its own after them; a path dropped on the Dock icon at launch keeps its tab and stays shown, with the saved tabs beside it; with none kept (a settings file from before tabs), or none of their folders still there (a drive not mounted, a folder moved; `FirstSavedTab` names the one the welcome view says is opening), the repository of the last run opens, and a frame left empty gets the welcome view's buttons back (`ShowOpening('')`).
- `gittan.settings.pp` holds `TGittanSettings`, an ini file in a folder named `Gittan` next to the one `GetAppConfigDir` gives (`~/.config/Gittan/gittan.ini` on Unix; `ConfigDir` keeps the folder off `Application.Title` (Git Tree Analyzer & Navigator; Gittan on Cocoa, where the application menu's About, Hide and Quit items name it and would lose the ampersand as an accelerator), which `GetAppConfigDir` would name it after): the window bounds and state (with none, or none on a screen now, `PlaceWindow` in `uwindow.pp` opens the window in the middle of the main screen's work area, `FirstShare` of it, at least the designed size and at most `FirstMaxWidth` by `FirstMaxHeight` at 96 DPI), the tree width, the editor font and zoom, the width of a tab (`TabSize`, 0 for `DefaultTabSize`, 8, git's own; `FTabSize` in the frame, set on every editor in `SetupEditor` and changed through `ApplyTabSize`, written as 0 when it is the default), the view options (word wrap, hidden unchanged lines, context lines, side by side, blame), an external editor command, a terminal command (File > Open in Terminal (Cmd+Alt+T) and the status bar's menu run it with the repository root appended, and a command of the Commands page marked for the terminal with the root and then its command line, `OpenTerminal` in `umain.actions.inc`, see repo-commands.md; empty opens the platform's terminal: `open -a Terminal` on macOS, Windows Terminal or `cmd.exe` on Windows, the first of `x-terminal-emulator`, `gnome-terminal`, `konsole`, `xfce4-terminal` and `xterm` on PATH elsewhere, started in the root), the path of git to run in place of the one found on PATH (`GitPath`, section `Tools`; empty for the found one), whether the open repository is fetched in the background and how many minutes apart (`AutoFetch`, on by default, and `AutoFetchMinutes`, `DefaultAutoFetchMinutes` 10, kept within 1 to 240; on the Tools page under git, see commit-and-remote.md), whether the hosting features are on, for every forge at once (`HostingEnabled`, section `Hosting`, on by default; an older file's `Enabled` in a forge's section, GitHub's, turns it off when off and is taken out on save, tested in `TestOldForgeSwitch`), each forge's tool (`ForgeCliPath`, `Cli` in a section named after the forge, empty for the one found; an older file's `Gh` in `Tools` is read as GitHub's and taken out on save, tested in `TestOldGhPath`; github.md), and whether the forge view looks for clones beside the recent repositories (`CloneSiblings`, off by default), whether the AI features show, the agent they run (Claude Code or GitHub Copilot) and each agent's command and model (section `AI`; ai.md), the recent repositories, and the commands files trusted (`[Trust]`, `CommandsTrusted`, `TrustCommands`; repo-commands.md). The editor font has no fixed default: with none picked (`FontName` empty, `FontSize` 0) it is `DefaultFontName` (Menlo on macOS, Consolas on Windows, Monospace elsewhere) at `DefaultFontSize` for the height of the screen the window opens on in logical pixels (9 on macOS, 10 elsewhere, one more from 1200 and another from 1600; `FDefaultFontSize`; the LCL's Cocoa makes a size a third larger than a native point, so 9 is Terminal's and Xcode's 12), and the frame's `FormClose` writes the name and size only when they differ from these, so the default keeps following the screen; the Courier New 9 earlier versions wrote (ATSynEdit's own default, never picked) is read as no choice. `ApplySettings` in `umain.actions.inc` applies it before the menu is built, `FormClose` saves it. The settings dialog (`gittan.settingsdlg.pp`, `EditSettings`, from `MenuSettingsClick`; Cmd+, in the application menu on macOS, which the LCL builds from `CocoaConfigMenu.appMenu.customMenus` when the menu is set, and Tools > Settings with Ctrl+, elsewhere) has five pages (`TSettingsPage`) picked in a sidebar of the main window's kind (a `TGittanSideNav` with the icons `niEditor`, `niTools`, `niForge`, `niAI` and `niAbout`, colored with `ThemeSideNav` on `SidebarShade`, which `ColorSidebar` in `umain.pp` uses too; each page is an autosized panel in the content beside it, shown one at a time by `ShowPage`, all held at the tallest one's height from `DoShow`, the preferred height of each page not shown, so the dialog keeps its size): Editor edits the editor font and its size (View > Font has the font too; both go through `ApplyEditorFont`), the tab width and the syntax theme (View > Syntax Theme too; both go through `SetSyntaxTheme`); Tools edits the editor and terminal commands, each with a hint for what an empty field does, and the path of git, with a note under it that says what will run: where the tool is found on PATH, or that it is not, or whether the path typed exists; Hosting has a block per service that hosts repositories under its name in bold, GitHub alone so far (another service, GitLab with glab, is another block and section): Turn on the GitHub features (`FGitHubBox`, `GitHubChange`) with a note on what they are, and gh's path with the same kind of note (for gh that the GitHub features are off when none is found), then Look for clones beside the recent repositories (`FSiblingsBox`, `CloneSiblings`) with a note, both enabled only with the switch on; AI turns the AI features on and picks the agent, with its command's path and its model (see ai.md); About, the last, which Gittan > About Gittan on macOS (before Settings in `customMenus`) and Tools > About Gittan elsewhere open (`MenuAboutClick`; `OpenSettings` takes the page, `EditSettings` its `APage`), shows the icon (`LoadAppIcon`: `Application.Icon`, empty under Cocoa, else `MAINICON` from the executable's resources, the .ico's largest image, resampled with BGRABitmap's `rfBestQuality` in `AppIconPaint` to a square as wide as its box in the screen's pixels, in the middle of the box's height, which `alLeft` makes that of the text beside it), the name, the tagline and the build (`CurrentBuild`, or a local build with its compile date), a Check for Updates of its own (a `TGittanUpdateJob` the dialog owns; one still running when the dialog closes is dropped and goes to `GUpdateZombies`, freed once it has finished, so closing does not wait for the request, which gives up after `FetchSeconds`; its answer is beside the button, past the snooze: a link to download a newer build, a link to the latest release when this build cannot be compared with it, this is the latest build, or why GitHub could not be asked), what Gittan runs on and with (`ReadVersions`, queued the first time the page shows; it finds the tools and a `TVersionsJob` asks their versions in a thread, so the dialog stays live while the agent's node starts, and again when the page shows after a tool field, a switch or the agent changed (`FVersionsRead`, dropped by `ToolChange`, `GitHubChange` and `AIChange`), since the lines name the tools as the fields have them: the build, `git --version`, `gh --version` (or that the GitHub features are off) and the agent's `--version` as the fields name them now, or that the AI features are off, the system with its version (`sw_vers`, the Windows version, `/etc/os-release`), the CPU and the widgetset, Free Pascal and the LCL) with Copy, which puts those lines on the clipboard for a bug report, links to gittan.app and the source, and the licenses of Gittan and what it is built with. While About shows, OK keeps the focus, since a focused button becomes the default under Cocoa and Return would check for updates. `EditSettings` takes the values besides the font as a `TSettingsValues`. The other view options stay in the View menu. The font, the theme and the tab width are previewed in the editor itself: the dialog calls `PreviewSettings` on every change, and `MenuSettingsClick` puts back the font, theme and tab width it had when the dialog is cancelled. The dialog also has a read-only sample editor of its own (`FSampleEdit`, with its own `TATAdapterEControl`) under buttons for Pascal, C++, JavaScript, TypeScript and Python (`Samples`), so the colors show whatever the main editor holds and wherever the dialog sits: it takes the lexers from `FLexers` and the colors and zoom from `Edit`, and `StyleSample` sets its lexer again after every change, since `TGittanLexers.ApplyTheme` recolors the lexers every editor shares in place (so the sample can only show the theme the main editor has, which is why the main editor previews too). As in `SetEditorLexer`, assigning the lexer needs `DoEventChange(0)` to start the parse. The dialog opens with its bottom right corner near the editor's, so the code at the left stays in view (placed in `DoShow`, once its autosized size is known); opened on About (`FCentered`), which has nothing to preview, it is centered over the main window, as the other dialogs are (`poMainFormCenter`). The dialog changes `FSettings` only; the file is written on close as before, so an edit of the ini while Gittan runs is still lost. With no argument on the command line Gittan reopens the most recent repository. The argument or that repository (`StartRepository`) opens in `OpenAtStartAsync`, queued from the window's `FormCreate` (`uwindow.pp`, as `StartRepository`), so the window is shown and painted first, with the welcome view already saying what opens (`SetBusy`) rather than offering its buttons for that moment; the repository's git work then runs in a thread (`TGittanOpenJob`, see git-core.md). A folder or file dropped on the Dock icon at launch that is open or opening by then stays (the repository is open, an open job runs, or the view is no longer the empty summary). The ini is written only on a normal close; a killed process keeps the previous one. TIniFile trims every value and takes a pair of quotes around one off as it reads, so `KeepEdges` writes a string that starts or ends with a space or a double quote inside quotes of its own (a quoted editor path such as `"C:\Program Files\Code\Code.exe"` stays quoted); the commit draft goes through `EscapeLines` first, which writes a line end as `\n` and a backslash as `\\`. Tested in `tests/testsettings.pp` (`TestQuotesAndSpaces`).
- Tools > Install CLI Command (`MenuInstallCliClick`, `gittan.cli.pp`) installs a `gittan` command that opens a folder or file in Gittan, the current folder when none is given. It is a script naming the running executable by its full path (`Application.ExeName`), so installing again after moving Gittan updates it. macOS: `/usr/local/bin/gittan` runs `open -a <bundle>` (`MacBundleOf`: the bundle the executable is in, or `Gittan.app` beside it, since a build's bundle holds a link to `./Gittan` and a Gittan started as that file gets no Dock icon or menu bar; the plain Unix script only when there is no bundle), so a running Gittan gets the path through Cocoa's open-files event, which the LCL hands to `FormDropFiles`; `/usr/local/bin` belongs to root, so the copy then goes through `osascript ... with administrator privileges`, and a Gittan run from a disk image or translocated by Gatekeeper is refused. Windows: `%LOCALAPPDATA%\Gittan\bin\gittan.cmd` runs `start`, and that folder is added to the user's `Path` in `HKCU\Environment` (then `WM_SETTINGCHANGE`, so only new terminals see it). Elsewhere: `~/.local/bin/gittan` starts the executable with `nohup` in the background, and the message says how to add the folder to PATH when it is missing. Every script carries a marker line (`IsGittanScript`); a `gittan` without it is someone else's and is neither replaced nor removed. Tools > Uninstall CLI Command (`UninstallCli`) removes the script (as an administrator on macOS when needed) and on Windows the empty bin folder and its PATH entry (`PathListRemove`); the item is enabled only while the script is there (`CliInstalled`, checked in the Tools menu's `OnClick`, which runs as it opens). The script texts, the PATH helpers and the marker check are tested in `tests/testcli.pp`; installing and removing are not.
- `gittan.update.pp` (no LCL, tested in `tests/testupdate.pp`) looks for a newer Gittan, as Trndi does: `TGittanUpdateJob` asks GitHub's `releases/latest` in a thread (`FetchUrl`, through `gittan.http`, below), `ParseRelease` reads the tag, title and page, and `IsNewerRelease` compares the tag's number (`BuildOfTag`, build-<n>) with `CurrentBuild`, the compiled-in `GittanBuild`; a local build (-1) is never told about one. The messages name this build by `CurrentBuildName`: the compiled-in `GittanVersion` (0.9.123, `GITTAN_VERSION`, see AGENTS.md), or build and its number without one; About shows Version and it. `TGittanApp` (`gittan.app`) starts a check `UpdateFirstCheck` ms after start and every `UpdatePoll` ms after that, only in a build with a number, and tells the window through `OnUpdateChecked` (`UpdateChecked` in `umain.update.inc`); a newer release puts the badge in the status bar (`ShowUpdateBadge`) with a hint, unless `UpdateSnoozedUntil` in the settings (section `Update`, a yyyy-mm-dd day) is still ahead (`UpdateDue`). A click on it opens `UpdateDialog`: Download opens the release's page, Remind Me in 14 Days (`UpdateSnoozeDays`, `SnoozeUpdate`) sets the snooze and hides the badge, Not Now closes it. Tools > Check for Updates (`App.CheckForUpdate(True)`) always answers in a dialog, past the snooze: the same dialog for a newer build, else up to date, a local build with the latest release named, or why GitHub could not be asked (`HttpFailure`). The app keeps the last finished job until the next check or until it is freed, since the job is still in its thread as it reports.
- `gittan.http.pp` (no LCL, tested in `tests/testhttp.pp`) makes HTTP and HTTPS requests with what each platform has, as Trndi does (its `nsutils.web.urlrequest`, `winutils.httpclient` and `trndi.curl`, cut down): NSURLSession on macOS (an ephemeral session per request with a delegate, since FPC 3.2 has no blocks; the FPU's exceptions masked while Apple's code runs, on the calling thread and in the delegate's callbacks on the session's queue), WinHTTP on Windows (the system's proxy, TLS 1.2 and 1.3 asked for, `SplitUrl` for what `WinHttpConnect` takes, the 12xxx messages from winhttp.dll's table) and libcurl elsewhere, loaded with `dynlibs` on the first request (`CurlLoaded`, under a lock, `curl_global_init` there) so Gittan starts without it, and `curl_easy_setopt` and `curl_easy_getinfo` typed `varargs`, as Apple's arm64 ABI passes variadic arguments on the stack. Gittan links no TLS library of its own. `HttpRequest` (and `HttpGet`) waits for the answer, so a job's thread calls it, and gives the request up when `ACancel` (a `TGittanHttpCancel`, asked every quarter second while it waits) says to: NSURLSession's task is cancelled, libcurl's progress callback (`CurlProgress`) ends the transfer, and on Windows the synchronous call is left to a thread of its own (`TGittanWinHttpSender`, which frees itself when it ends, by WinHTTP's timeouts at the latest), since WinHTTP's documentation rules out closing a synchronous request's handle from another thread; a request given up comes back with Status 0 and `HttpGivenUp`. It follows redirects, sends `HttpUserAgent` unless the headers name a User-Agent, and returns a `TGittanHttpResponse`: any status is an answer with its body (`HttpOk` for a 2xx, `HttpFailure` for a message), Status 0 with `Error` when none came. `HttpBackend` names the backend. Defining `GITTAN_CURL` builds the libcurl one on macOS too, which is how it is tested there: `fpc -dGITTAN_CURL` with the test build's options and its own `-FU`. The tests run against a server of their own in a thread (`TTestServer`, the `sockets` unit, 127.0.0.1 on a port the system picks, as Trndi's test server but without a fixed port), over plain HTTP: echo, 404, redirect, refused, timeout and given up.
- `UpdateStatus` fills the repository parts whenever one is open, since the header names the file and its lexer; without one the name is the path of a plain file. It leaves the message and the position alone. `UpdateStatusPosition` (from `UpdateChangeNav`, so on every caret move) shows "Ln 12, Col 4" in the change view and a plain file: the file's line from `FileLineOfRow`, or the old side's number with "(old)" for a deleted line; nothing in the summary, the repository diff or the history. A note goes through `StatusNote` (`StatusNoteSeconds`, `StatusErrorSeconds` in red) and clears itself; a message that says something is under way ("Looking for ...", "Loading history...", fetching a pull request) is shown with `ShowMessage(..., 0)`, which stays, and the code that finishes the work calls `ClearMessage`. A repository that fails to load keeps its error in red until the next message. `UpdateStatus` also checks the Syntax menu: Automatic (the lexer from the file name; `FManualLexer` is set by a manual pick and cleared when the view changes), and the lexer in use, found through the item's `Hint`, which keeps the name without accelerator ampersands.
- `UpdateCaption` names the window after the repository, or after the file when none is open; the header names the file, so the title does not change with the selection.
- Questions, notes and short inputs go through `gittan.askdlg.pp`, not the LCL's `QuestionDlg`, `MessageDlg`, `InputQuery` or `InputBox`, which on Cocoa laid a message out on one line as wide as the screen allowed, put a glyph on every button and centered the buttons. `AskDlg` takes the buttons as `QuestionDlg` does (a modal result, an optional caption, then `IsDefault` or `IsCancel`, or `NoCancel` after any button for a question that must be answered: Escape does nothing and `CloseQuery` keeps the close box from closing it, by whether a button was pressed (`FPressed`), since the LCL's `Close` has set `mrCancel` by the time the modal loop asks; overloads take its help argument, so a call changes in its name alone), `TellDlg` a note with OK, and `AskInput` (`AskText` for one field) fields with a label over each, an optional note, OK named for what it does, off while the first field is blank (unless `AOptional`) or the caller's `TGittanAskCheck` says why the fields cannot be taken, which shows in red under them as they are typed. The form is built in code like the Who Commits dialog: 460 wide, the text wrapping (its labels with `ShowAccelChar` off, so an `&` in a branch name shows), a warning triangle or an error disc at the left for those kinds and the mark of `gittan.dialogicon` for the rest (icon.md), 48 points, `IconLeft` in from the edge and in the middle of the text's height over the buttons (`IconRect`), painted on the form in `Paint` rather than as a control, since a control counts in the form's AutoSize and moving it down made the form taller, which moved the buttons and the icon again until it crashed, on macOS without a title bar, as a system alert has it (`MakeAlertWindow` in `gittan.titlebar.pp`, from `CreateWnd`: the bar transparent, the title hidden but kept for Mission Control and the Window menu, no close, minimize or zoom button, the content under the bar rather than reaching under it, since the LCL sizes a full size content view's window as if the bar were not there) and the title as the first line in bold (`AlertHeading`, `TopGap`), the right and bottom edges as wide as the icon's left one (`EdgeGap`), since the bar's strip leaves some 30 points over the title (the button row's sides are set one by one: `BorderSpacing.Around` adds to each side's own), while Windows and GTK 3 keep the title bar, plain buttons at the right, on macOS the default rightmost with the cancel button left of it, elsewhere the default first. The checks: a new branch's name (`BranchNameProblem`: `IsBranchName`, and not taken; Rename takes the old name as no change), a tag's (`TGittanRepo.IsTagName`, `check-ref-format refs/tags/<name>`, tested, and not taken: `HasRef`, unpeeled, so a tag of a tree or a blob counts), a path to move a file to (`MoveTarget` in `umain.movefiles.inc`, also run on OK: inside the work tree, out of `.git`, nothing there yet), a worktree's folder (not there yet) and branch, and Compare With > Other's commit (`HasCommit`, a range left to `SetBase`).
- A field holding a path shows its end, the part that tells one folder from another: `ShowPathEnd` in `gittan.pathfield.pp` sets the Cocoa cell to truncate at the head ("…/scratchpad/demo" without the focus) and, as the field takes the focus, scrolls the field editor to the end from the message loop, the selection kept, since the field editor selects everything and scrolls to the start after the LCL's `OnEnter` (it takes `OnEnter` when that is free, and a `TPathEndHook` with free notifications keeps the queued call off a field that is gone); elsewhere the caret goes to the end. `ShowTextStart` undoes it (the cell truncating at the tail, the field no longer watched), for the settings' agent field while it holds an API's server (`ShowAgentEnd`), whose start names the host. It is called from the dialogs' `DoShow` (and the settings dialog's `ShowPage`, since a page not shown yet has no handles): Clone's folder (also after Choose...), Add Worktree's folder (`AskInput`'s `APathField`), and the settings' git, forge tool and agent paths.
