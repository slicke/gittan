# .gittan/repo.toml

Read this when touching `gittan.repoconfig`, `LoadRepoConfig`, `CommitConfigNote`, `EffectiveIssueTracker`, the subject's limits in the Commit section, sign-off's default, the template's fallback, or the protected branches. The user's reference for every file of the `.gittan` folder is `docs/gittan-folder/README.md`; keep it in step. The commands files are in repo-commands.md.

- `.gittan/repo.toml` is what a repository says of itself for everyone who clones it, and only describes: nothing in it runs, so it needs no trust, unlike the commands files. `gittan.repoconfig.pp` (no LCL, tested in `tests/testrepoconfig.pp`) reads it with toml-fp: `ReadRepoConfig(ARoot)` gives a `TGittanRepoConfig` (`Exists` false without the file; a file that is no TOML has `Error` and every value as if missing; the banner says so with the reader's message, `NoteRepoConfigError`, when the repository opens and when `LoadRepoConfig` reads another error), `ParseRepoConfig` the same from a text, `EmptyRepoConfig` the defaults. A value of another type than the one asked for is left out. `RepoConfigTemplate` is a commented example whose example lines, uncommented, are the whole file (tested). Where git config sets the same thing (bugtraq.*, commit.template, gittan.signOff), git config comes first.
- `project =` (a string split on commas and spaces, or an array; `"none"` for no kind): `ProjectsOfFiles` in `gittan.repocommands` reads it after the kinds picked on the Project page and before the `project =` line of commands.toml (project-kinds.md).
- `[issues]` `url`, `regex` and `ids` are `bugtraq.url` and `bugtraq.logregex` (`ids` its second line; without `regex` there is no tracker), in `Issues`; a `url` that is no `http://` or `https://` address is left out, since a clone's file is not to hand a click to whatever program another scheme opens. `EffectiveIssueTracker` (`umain.issues.inc`) takes them when the config's tracker (`FIssueTracker`, from the snapshot) is empty (no expression; a `bugtraq.url` set alone still gives the address), for `UpdateIssueTracker` and `SummaryIssueClick`; Repository > Issue Tracker... still edits git config alone.
- `[commit]`: `subject-limit` and `subject-max` (1 to `MaxSubjectLimit`, else left out) are `SubjectSoft` and `SubjectHard`, `DefaultSubjectSoft` (50) and `DefaultSubjectHard` (72) when not set; a maximum under the limit (its own or the default) pulls the limit down to it, a limit over the default maximum raises the maximum when the file sets none (a maximum the file sets holds, tested in `TestLimits`). `UpdateSubjectCount` uses them, and the count's hint names the file when the maximum is its own (`rsSubjectCountHintRepo`). `template` (a path from the root) is `TGittanRepo.CommitTemplate`'s `AFallback`, read only when git config names no commit.template, and only a file in the checkout (`FileInCheckout`: under the root, with neither the file nor a folder on the way a link), since a clone brings the path and the text goes into a message to be pushed; `../`, an absolute path, a link and anything in `.git` (whose config may hold a remote's token) are read as no template (tested in `TestCommitTemplate`). `sign-off` is the default of `TGittanRepo.SignOff(ADefault)` while `gittan.signOff` is not set in the repository's config; `SetSignOff(ASignOff, ADefault)` unsets the key when the choice is the default and writes `true` or `false` otherwise, so turning Sign Off off against `sign-off = true` is kept, and a later change of the file reaches a repository that never chose (tested in `TestCommitAmendAndHook`). `types` and `scopes`: `CheckSubject` reads the subject as Conventional Commits, `type(scope)!: text` (the type of letters, digits, `-` and `_`; a colon then a space or the line's end; scopes split on commas; types and scopes in any case), `scOk` without types, for an empty subject and for git's own lines (`Merge `, `Revert "`, `fixup! `, `squash! `, `amend! `), else `scNoType`, `scUnknownType` or `scUnknownScope` with the name in `ADetail`.
- `[branches] protected`: names or patterns (`GlobMatch`: `*` any characters, `/` too, `?` one); `BranchProtected` is false for an empty branch.
- The frame keeps the file in `FRepoConfig` (`EmptyRepoConfig` in `Init` and when a repository closes). The open reads it before `LoadCommitDraft`, so the draft's template and sign-off follow it; `ApplySnapshot` calls `LoadRepoConfig` (`umain.commit.inc`) before `UpdateIssueTracker`, so an edit or a pull is seen: a changed `sign-off` reads `SignOff` again, a changed `template` reads the template again and puts it in a field that holds nothing of the user's (`MessageBlank`, no operation, no Amend, no commit running), and the subject's count and hint follow. `CommitConfigNote` is the Commit section's note for the file (`UpdateCommitState`, after the stray rebase's note and before the tick hint, only with something to commit, Amend on or a message typed, and no operation, so the section still folds when idle): `rsProtectedBranchNote` while a protected branch is checked out (`FHeadDetached`, from the snapshot, keeps a detached HEAD's id out), with `HintBranch` as its glyph, else the subject's (`rsSubjectNoType` names the first type as the example, `rsSubjectUnknownType`, `rsSubjectUnknownScope`). The Commit button stays on: the file's rules are the team's, not git's.
- The Config section lists the file as it lists every file under `.gittan` (repo-files.md), so it opens and saves in the editor.
