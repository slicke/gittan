# Extensions

Read this when touching `gittan.ext.*`, `gittan.exthost`, `umain.ext.inc`, the Extensions menu, the Extensions page of the settings, `externals/quickjs/`, the libraries beside the executable, or an event the extensions get.

## What an extension is

- A JavaScript file (ES2023, run by quickjs-ng) in the user's extensions folder, `extensions` beside `gittan.ini` (`TGittanSettings.ExtensionsDir`; `~/.config/Gittan/extensions` on macOS and Linux). Every `*.js` at the top of the folder is one extension; subfolders hold ES modules an extension imports, confined to the folder (`gittan.ext.modules`). The engine, the manifest, the permissions, the module loader and the promise bridge came from Trndi's extension engine (`units/trndi/ext` there), with its dialogs and settings swapped for a host class, so `src/core` builds them without the LCL and the tests run them.
- The file starts with a manifest in a comment: `/* @name ... @copyright ... @version ... @description ... @homepage ... @license ... @perms net, exec */` (`gittan.ext.perm`, `ParseExtManifest`; a UTF-8 BOM and one `"use strict";` line may come first; an unknown directive or permission keeps the file from loading). Its id is the file's name without `.js` in lower case (`ExtIdFromPath`); two files that differ in case alone collide, and the second is refused.
- Permissions are groups (`TExtPermGroup`): `data` (the repository), `ui` (dialogs, cards, messages, commands), `timers` always granted; `net` (fetch), `exec` (git and programs) and `settings` (Gittan's own settings) only when `@perms` names them and the user said yes. The grant is kept with the file's SHA-256 (`gittan.ext.grant`; `ExtPerm` in the settings, section `ExtPerm:<id>` with `Hash`, `Granted`, `Author`), so an edited file asks again; a no is not kept and the file is skipped until the next load. A native an extension was not granted is not defined in its context, so `typeof Gittan.git === "undefined"` says what it may do, and `Gittan.permissions.require("net")` throws a readable error.

## The engine (`src/core`)

- `gittan.ext.quickjs` is the binding to quickjs-ng through Trndi's C shim (`externals/quickjs/tq_shim.c`): a JSValue is a 16-byte struct, so every value crosses by pointer, and every native is a plain Pascal procedure reached through one trampoline by its `magic`. The libraries are `libqjs` and `tqshim`, linked at link time (`{$LINKLIB}` on macOS, the `Libraries` path of `Gittan.lpi`, `-Fl` for the tests) and loaded from beside the executable: an rpath of `@loader_path` on macOS and `$ORIGIN` (and `$ORIGIN/../lib/gittan` for the packages) on Linux, set as `Conditionals` in both build modes; Windows looks beside the executable anyway. `make`, `make debug` and `make rebuild` copy them from `externals/quickjs/prebuilt/<cpu>-<os>` (`QJS_DIR`, FPC's names, aarch64 for Apple Silicon) into the project root before the link and into `Gittan.app/Contents/MacOS` after it (`stage_qjs`); `make test` copies them beside the test binary; `make packages` installs them in `/usr/lib/gittan`; CI copies them into the tar, the bundle (signed ad hoc each, since `codesign --deep` leaves loose dylibs alone), the zip and the installer (`dist/windows/gittan.iss`). On Linux the engine ships as `libqjs.so.<version>` and the `libqjs.so.0` and `libqjs.so` links are made by `qjs-links` and `stage_qjs` (git keeps no symlinks that survive NTFS). `.gitignore` lets the prebuilt libraries in. The macOS libraries were built with a minimum of macOS 11.0 (`clang -mmacosx-version-min=11.0`), the Intel ones cross-built on Apple Silicon (`build.sh mac-x86_64`); a rebuild of the engine is `externals/quickjs/build.sh` (needs cmake), see its README.
- `gittan.ext.engine` is `TGittanExtEngine`, one for the process (`Instance`; `Existing` never makes one; `ReleaseInstance` at the end, after which none can be made): one runtime, a context of its own per extension (`NewExtensionContext`), the `Gittan` class in each, the baseline natives (`alert`, `confirm`, `prompt`, `select`, `console.*`, `setTimeout` and the timers over `TFPTimer`, `performance.now` and `crypto` over `gittan.ext.sys`), the ES polyfills, the module loader, the promise bridge (`gittan.ext.promise`: a `TJSAsyncTask` thread runs a native marked threaded and settles the promise on the main thread through `Synchronize`), a 50 ms timer that drains the job queue (`PumpJobs`, public, which the tests call), a watchdog that aborts a script after 10 s of continuous JS (a native that waits, a dialog, restarts the budget) and a 64 MB heap for all contexts. `UnloadExtensions` tears every context down (the registry's values first) and keeps the runtime, which is what Reload does.
- `gittan.ext.host` is what the engine asks of the program: `TGittanExtHost` with the dialogs (`Alert`, `Confirm`, `Prompt`, `Select`, `ShowLog`), `ReportError`, `AskPermission`, the message loop (`Pump`, `Terminated`), the repositories (`ActiveRoot`, `RepoFor`, `StatsFor`) and the window (`AddCard`, `ClearCards`, `SetStatus`, `Notify`, `OpenFile`, `CommandsChanged`). `ExtHost` is the one in place, a default that answers nothing until `SetExtHost`; the window gives `TGittanExtUIHost` (`gittan.exthost`, over `gittan.askdlg` and the frames through `TRepoWindow.FrameForRoot`, `ShownFrame`, `FrameAt`) in its `FormCreate` and takes it back in `FormDestroy`, before the frames go; the tests give `TFakeExtHost` (`tests/testextengine.pp`).
- `gittan.ext.registry` keeps what the extensions registered: the commands (`Gittan.commands.register`: an id, a title, where it shows, the function), the listeners (`Gittan.on`) and the declared settings (`Gittan.settings.define`), each function a value the registry owns and frees with its context. The engine calls them by value (`RunCommand`, `Fire`), never by a global's name, so two extensions with the same function name do not collide.
- `gittan.ext.loader` finds and loads: `TGittanExtLoader.Load` reads the folder in name order, parses each manifest, hashes the file, skips one turned off (`ExtEnabled`, section `Extensions`, `<id>=0`), asks for its permissions, makes its context, lets `OnProvision` register Gittan's natives in it (`gittan.ext.api`) and runs it; what it found is `Infos` (`TGittanExtInfo`: the manifest, what was granted, whether it loaded, else why) for the settings page. `Reload` unloads (their cards go too) and loads again. The host's `CommandsChanged` is told once at the end (`Loading` is on meanwhile). `App.Extensions` is the loader; the window queues the first load after it is up, before the repositories open, so a permission prompt comes over the window and `repo.opened` reaches the listeners.
- `gittan.ext.api` is the API an extension sees. The natives of the `Gittan` class answer JSON text, and a facade evaluated in the context parses it into `Gittan.repo`, `.git`, `.exec`, `.gh`, `.net`, `.ui`, `.storage`, `.settings` and `.app`; a namespace whose natives were not granted is left out. The reads run on the main thread against the window's repository; `git.run`, `exec.run` and `fetch` run on the promise thread with strings alone (`RunGitEnv`, `RunCli`, `gittan.http`), never the window's objects.

## What an extension can do

| Member | Needs | Does |
|---|---|---|
| `Gittan.api` | | `version`, `extensionId`, `permissions`; `Gittan.permissions.has(n)`, `.require(n)` |
| `Gittan.repo.root()`, `.snapshot()`, `.files()`, `.diff(path?)`, `.fileText(path, ref?)`, `.blame(path, ref?)`, `.commit(hash)`, `.branches()`, `.tags()`, `.stashes()`, `.remotes()`, `.recent(limit?)` | data | the shown repository, or another open one with `{repo: root}` as the last argument; `snapshot()` is `TGittanRepoSnapshot` (`SnapshotJson`), `files()` the changed files (`FileStatsJson`), `fileText` the work tree's for no ref |
| `Gittan.git.run(args, {repo?})` | exec | a promise of `{ok, status, stdout, stderr}`, Gittan's git in the root |
| `Gittan.exec.run(cmd, args, {cwd?})`, `Gittan.gh.run(args)` | exec | a program found on the tool path (`FindTool`), or by its path; gh as the settings name it |
| `Gittan.net.fetch(url, init)` | net | fetch over `gittan.http` (GET, POST and the other methods; `init.timeout` in ms; no streaming) |
| `Gittan.ui.alert`, `.confirm`, `.prompt(caption, text, default)`, `.select(caption, text, options)` | ui | the dialogs (`gittan.askdlg`; `InputCombo` for select) |
| `Gittan.ui.notify(title, detail)`, `.error(title, detail)`, `.setStatus(text, seconds)`, `.clearStatus()`, `.openFile(path, line)` | ui | a banner, a line in the status bar (0 seconds keeps it), the file at a line |
| `Gittan.ui.addCard({path, line, side, title, text, severity})`, `.clearCards()` | ui | a card under a line of the change view, as the AI review's (`TGittanReviewThread` with `Extension` set, shown while the work tree is compared, no Fix link, the extension's name after ⚙); the extension's cards dropped |
| `Gittan.commands.register({id, title, where, run})`, `.unregister(id)` | ui | a command in the Extensions menu (`where` has `"menu"`, the default) and so in the command palette, in the file tree's popup (`"file"`) or the editor's (`"editor"`); `run(ctx)` gets `{repo, path, line, selection}` |
| `Gittan.on(event, fn)`, `Gittan.off(event, fn)` | | the events below |
| `Gittan.storage.get(k)`, `.set(k, v)`, `.remove(k)`, `.getJSON(k, default)`, `.setJSON(k, v)` | data | the extension's own values, section `ExtValues:<id>` of `gittan.ini` |
| `Gittan.settings.define([{key, type, label, default, options, note}])`, `.get(key)` | data | the fields of its settings page (`type` bool, string, number or choice); `get` is the value set there, else the default |
| `Gittan.app.setting(name)` | settings | `GitPath`, `EditorCommand`, `TerminalCommand`, `AIEnabled`, `HostingEnabled`, `ExtensionsDir`, `<Forge>Cli` |

The events (`GittanExtEvents`), each with `repo` in its argument: `repo.opened` (`branch`, `head`), `repo.changed` (the snapshot), `commit.before` (`message`, `paths`, `amend`), `commit.after` (`ok`, `error`, `id`, `amend`), `push.before` (`branch`, `remote`, `ref`, `kind`: push, force, branch or tag), `push.after` (`ok`, `error`, `kind`), `pull.before` (`branch`, `mode`), `pull.after` (`ok`, `error`) and `unload`. A `before` listener stops what is about to happen by returning `false`, a string (the reason) or `{cancel: true, message}`: the frame shows "An extension stopped it" with the reason and starts nothing (`ExtFire`, `umain.ext.inc`; `StartCommit`, `StartRemote`); every listener is called even after one stopped it, a listener that throws is reported and stops nothing, and a promise is not waited for. The frame raises them (`ExtEmit`) from `OpenJobDone` (`repo.opened`, then `repo.changed`), the end of `ApplySnapshot`, `CommitJobDone` and `RemoteJobDone`, all on the main thread.

## The window

- The Extensions menu (`FExtMenu`, after Tools) holds the commands registered for the menu, then Reload Extensions, Open Extensions Folder and Extensions Settings...; the command palette lists them as "Extensions: ...". The popups get theirs after a separator, tagged `ExtItemTag`. `RebuildExtMenu` (from `TRepoWindow.ExtensionsChanged`, which the host's `CommandsChanged` calls in every frame) builds them again from the registry; a click is `ExtCommandClick`, which gives the command the repository, the file (the popup's for a popup, else the one shown), the line under the editor's popup or the caret, and the selection. The forge view has no Extensions menu.
- The Extensions page of the settings (`pgExtensions`, `gittan.settingsdlg`): the extensions found, ticked while they load, what the one picked is and its permissions or why it did not load, Open Folder, Reset Permissions (asks again at the next load) and the fields the extension declared; OK writes the values (`SetExtValue`, kept as they are), the ids turned off (`SetExtEnabled`) and the resets (`ClearExtPerm`), and reloads when one was turned on or off or reset (`OpenSettings`, `umain.actions.inc`). The dialog gets it all through `TSettingsValues` (`ExtInfos`, `ExtDefs`, the lists) and names no unit of the engine.
- Errors reach the shown frame's banner (`ReportError`): a manifest that is wrong, a script that fails to load (the engine's `ExtError`), a native that raises; `console.log` is a dialog with the text.

## Tests and docs

- `tests/testextperm.pp` (the manifest), `tests/testextmodules.pp` (the modules), `tests/testextquickjs.pp` (the binding, which loads the libraries), `tests/testextengine.pp` (the engine with `TFakeExtHost`: commands, listeners and cancelling, dialogs, the permission gate, unload), `tests/testextloader.pp` (the folder, on and off, the grants kept and reset, reload) and `tests/testextapi.pp` (the API against a temporary repository, git and a program through the promises, storage, settings, what a permission left out hides). `make test` stages the libraries beside the test binary; on the Intel macOS leg they load under Rosetta.
- `docs/extensions/README.md` is the guide for extension writers, `docs/extensions/gittan.d.ts` the types, `docs/extensions/samples/` three extensions: a commit message lint that stops a commit, a push notifier that posts to a webhook from its settings page, and a command that shows `git shortlog` and marks a file's last commit as a card.
