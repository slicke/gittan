# Blame, code history and the time-lapse

Read this when touching `gittan.blame`, `gittan.history`, `gittan.timelapse`, `gittan.timelapsebar`, `umain.blame.inc`, `umain.history.inc`, `umain.timelapse.inc`, Go > Code History or Go > Time-lapse.

- View > Blame (Cmd+Shift+B) shows in the change view who last changed each line (`umain.blame.inc`, `gittan.blame.pp`). `TGittanRepo.Blame` runs `git blame --porcelain` for a path in a commit, or in the work tree when the commit is empty; `TGittanBlame.Parse` reads the output into the commits and the commit of each line, and `TGittanBlameJob` runs the two sides of a file (the base, and the work tree or the right commit of a range, from `DiffSides`) in a thread, since a long history takes a while. A line of the new side is blamed in that version, a deleted line in the base; the old side of the side-by-side view is blamed in the base throughout. The results are cached per commit and path and dropped by `ClearBlameCache` whenever `LoadRepository` runs, since a reload may mean a new HEAD or work tree; a job no longer wanted is abandoned (`AbandonBlameJob`) and freed later rather than waited for. The band is a gutter band of Gittan's own tag (`gutterTagBlame`), leftmost, which ATSynEdit sizes but does not paint: `DrawBlame` paints the author and the age (`BlameAge`: today, 3d, 2w, 5mo, 3y) at the first visible row of each run of rows with the same commit from `OnDrawEditor`, and `BlameHintAt` gives the hover hint (short hash, author, date, summary) that `EditMouseMove` shows through the hover timer. Uncommitted lines are shown as "Not committed" in italics. A click on a cell (`EditClickGutter`, through `OnClickGutter`) shows its commit: `ShowBlameCommit` sets Base to `TGittanRepo.CommitRange`, the range from the parent (or from the empty tree for a root commit), and `BaseLabel` names it "vs commit abc1234" while `FBlameRange` matches; Compare With > HEAD (Working Tree) goes back.
- Go > Explain Line History with AI has the AI agent explain, from the same `git log -L`, how the selected lines or the caret's came to be, as a card under them (ai.md).
- Go > Code History (Cmd+Shift+H) shows how a piece of the shown file changed over its last commits (`umain.history.inc`, `gittan.history.pp`): the piece as it is now with the past of every line under it. The piece is the selection when it spans more than one row (a word selected by Go to Symbol is not it), else the innermost code tree range around the caret (`EnclosingRange`, the fold ranges with `DisplayInTree` as `CodeTree` reads them, the end row from the range's `EndIdx` token), else the whole file as the range 1..`WholeFileLines`, which git clamps. `ChunkLines` maps the editor rows to file lines in the commit the history starts from (`HistoryRef`: the right commit of a range, else the base, HEAD by default) through `FNewNum` or `FOldNum`, so lines added in the work tree do not shift the range; rows that are all new have no history. `TGittanRepo.LineHistory` runs `git log -L from,to:path [ref]` (or `git log -p -- path` with from 0) with `--format=%x01%H%x1f%an%x1f%at%x1f%s`, and `TGittanHistory.Parse` reads the commits with their hunks (`TGittanHistoryCommit`: a `TGittanBlameCommit` plus `TGittanHistoryHunk`s with the start lines from the `@@` header). `TGittanHistoryJob` runs it in a thread like the blame job (abandoned jobs share `FBlameZombies`, a `TGittanJobReaper` of `gittan.job`, tested, which frees a job once its thread has ended, `FreeFinished` from `FreeBlameJobsAsync`, and waits for the rest when it is freed), `HistoryStep` (5) commits at a time plus one to know whether there are older ones. A file the commit the history starts from lacks (untracked, or added since; `FileSize` at that commit) is not asked of git: the job reports `NotCommitted` and the status bar says the lines are not committed yet (`rsNoHistoryYet`); when the ref given names no commit (`HasCommit`; HEAD may name none yet in a new repository and is left out), the history job and the time-lapse job report `rsNoSuchCommit` as their error instead (tested in `TestNotCommitted`), where `git log -L` refused with "There is no path ... in the commit". A failure the banner shows clears the busy message first (`StatusNote` with an error goes to the banner, not the status bar); the changes not committed yet come first as a commit of their own (`AddUncommittedHistory`, the file's diff against HEAD cut to the range, only while the base is HEAD). `TGittanHistory.Layers` (tested) chains the hunks newest first: the new side of the newest commit is the current text, a commit's deleted lines are paired in order with the added lines in their place as their earlier versions, unpaired deleted lines are removed lines kept after the line before them, and the old side of each commit is matched by text, in order, to the new side of the next older one. The result is `TGittanHistoryRow`s: a current line (with its number in the newest version), the older versions under it, and removed lines, each with the commit it comes from (-1 when older than the history). `BuildHistoryView` puts them into the change view's fields (`GapFrom` holds the row's commit, so the blame band, hint and click work through `CommitOfRow` in `umain.blame.inc` without a blame, and a band click goes through `ShowHistoryCommit`): a legend row per commit first (`rowCommit`, `bmCommit`, bold through `MarkHeader`, the text from `HistoryHeaderText`: a swatch colored by `MarkSwatch`, short hash, date, author, summary, lines added and deleted; the author and summary composed with `GetDarwinNormalizedFilename`, since macOS gives git a decomposed name the editor would paint as two characters), a filler, then the rows: each tinted by its commit through bookmark kind `bmHistoryBase` + commit (`EditCalcBookmarkColor` maps it to `HistoryColor`: a fixed palette of six hues taken in turn, in three tones from `THistoryTone`, faint for the rows, stronger for the words and darker in light mode (lighter in dark) for the swatch, which is text and keeps 3.4:1 or more against the background; each tone is one OKLCH lightness and chroma, so no hue looks lighter than the others, and the hues keep away from the diff's red and green), an older version in italics and a removed line struck through (attribs tagged `tagHistoryStyle`), and the words that changed between a version and the one before it shaded in the strong tint (`MarkHistoryWords`, tag `tagHistoryWord` with the commit in `TagEx` so `RecolorWords` can follow the theme). A band of its own next to the text (`gutterTagInitial`, `InitialCols` wide, shown by `SetInitialBand` from `ApplyBlame` in the history view only, whatever View > Blame says) puts the author's initial on every row with a commit, legend rows included (`DrawInitials`, through `CommitOfRow`): the first letter of the composed name in upper case (`NameInitial`) on a flat rounded badge in the commit's row tint, the letter bold in its swatch tone; the changes not committed yet take the initial of `TGittanRepo.UserName` (`git config user.name`, read into `FHistoryUser` by `BuildHistoryView`), and a line older than the history gets none. A click or the hint on the band works as on the blame band. A last `rowMore` row fetches `HistoryStep` more while git had more. `EditMouseUp` sends a click to `HistoryClick`: a legend row shows the commit against its parent and opens the file at the hunk's first line, the more row fetches more at the same scroll position. `RefreshRepository` runs the job again for the same piece. `ChangeBlocks` skips legend rows, so the navigator counts the tinted runs. Side by Side and Hide Unchanged Lines do not apply to the view. After a commit the stored line range may no longer match the function; the command is run again from the file then.
- Go > Time-lapse (Cmd+Alt+H, also in the View chip under History) plays the shown file through every version its history has, oldest first (`umain.timelapse.inc`, `gittan.timelapse.pp`, `gittan.timelapsebar.pp`). `TGittanRepo.FileTimeline` reads the file as `HistoryRef` has it (`cat-file blob`, as stored, so a Git LFS pointer is what is followed) and `git --literal-pathspecs log --first-parent -m --follow -p -U0 -n 1000` up to that commit (the newest `TimelapseMax` commits, since each keeps a version), formatted as `LineHistory`'s so `TGittanHistory.Parse` reads it; a merge counts with its diff from the first parent, and only commits on the first parents are versions. A file with a NUL is binary and is not played. `TGittanTimelapse.Build` (tested in `tests/testtimelapse.pp` against git's own copy of every version, through a change, an addition, a deletion, a rename and a merge) makes each older version from the newer one by undoing the commit's hunks: with no context lines a hunk's new start is its first added line, or with none added the line after which the deleted ones stood; the added text is checked against the version, and a commit whose hunks do not fit ends the walk there (the history is cut to the commits it got through). Only every `TimelapseMarkEvery`-th version (32) is kept whole, with each commit's edits (`TGittanLapseStep`: at a place, so many entries out and these in), so memory follows the changes rather than a copy of the file per commit; `Lines` makes a version from the whole one at or after it, or from the version it made last when that is newer in the same stretch, as stepping back is (`TestLongHistory`: more commits than a stretch, every version asked for back, forward and across the marks). A line kept from one version to the next is one entry, with the commit it came in with (`Born`, the oldest commit for a line older than the history) and the one that took it away (`Died`). `TGittanTimelapseJob` runs it in a thread and is abandoned as the history job is (`FBlameZombies`); a file HEAD (or the base) lacks gives no time-lapse and no error, so the status bar says the file has no committed history (`rsNoTimelapse`) instead of git's "exists on disk, but not in 'HEAD'", and an error clears the busy message before the banner shows it (tested in `TestNotCommitted`). The view is the history view (`gvHistory`) with `FTimelapse` set and the commits in `FHistory`: `ShowTimelapseVersion` puts one version's lines into `FChangeLines`, `FRows` and `FNewNum`, each row's `GapFrom` the commit its line came in with, so the blame band, the initials band, the hint, a click on the band and Show Commit work as in Code History. A line has its commit's row tint (bookmark kind `bmHistoryBase` + the commit's hue); a line the version shown brought in has the diff's strip and the word tone as its row's background (`bmHistoryNew` + the hue), and `ChangeBlocks` counts only those, so the navigator and F7 step through what the version changed. While it plays, a step to a commit that takes lines away first shows the version before it with those lines struck through on the deleted color, two fifths of the step, then the new version; a version stays `TimelapseStepTime` (1.5 s, less for a long history so the whole plays in about 40 s, never under 0.25 s), the view scrolls what changed to a quarter down when it is out of view, and the play ends at the newest version (a play then starts over from the oldest). Filling the editor can run the message loop, so a step asked meanwhile (a key, the timer, a refresh) is dropped (`FTimelapseFilling`) rather than rebuilding the rows being filled. `TGittanTimelapseBar`, aligned to the bottom of the editor panel, has the play button, the commit of the version shown (short hash, date, author, summary) with a counter, and a track with a dot per version in its commit's swatch tone (left out when closer than 6 px) and a knob that a click or a drag moves (`OnSeek`); playing goes on from there. Space plays and pauses, Left and Right step back and forward while the editor or the bar is the window's active control (the editor gets the focus when the time-lapse starts). A refresh draws the version again, but after a commit that took the file (it was changed before and is not after it), the history or time-lapse gives way to the summary, as the change view of a committed file does (`CommitJobDone`); showing anything else ends the time-lapse (`EndTimelapse`, from `ShowEditor`, `LeaveEditorViews`, `ShowImageChanges`, `ShowBinaryChanges` and `ShowBinaryFile`). A job abandoned while git ran skips building the versions (`Terminated`), and one whose repository does not open says why. The changes not committed yet are not a version.
