# Blame and code history

Read this when touching `gittan.blame`, `gittan.history`, `umain.blame.inc`, `umain.history.inc`, Go > Code History.

- View > Blame (Cmd+Shift+B) shows in the change view who last changed each line (`umain.blame.inc`, `gittan.blame.pp`). `TGittanRepo.Blame` runs `git blame --porcelain` for a path in a commit, or in the work tree when the commit is empty; `TGittanBlame.Parse` reads the output into the commits and the commit of each line, and `TGittanBlameJob` runs the two sides of a file (the base, and the work tree or the right commit of a range, from `DiffSides`) in a thread, since a long history takes a while. A line of the new side is blamed in that version, a deleted line in the base; the old side of the side-by-side view is blamed in the base throughout. The results are cached per commit and path and dropped by `ClearBlameCache` whenever `LoadRepository` runs, since a reload may mean a new HEAD or work tree; a job no longer wanted is abandoned (`AbandonBlameJob`) and freed later rather than waited for. The band is a gutter band of Gittan's own tag (`gutterTagBlame`), leftmost, which ATSynEdit sizes but does not paint: `DrawBlame` paints the author and the age (`BlameAge`: today, 3d, 2w, 5mo, 3y) at the first visible row of each run of rows with the same commit from `OnDrawEditor`, and `BlameHintAt` gives the hover hint (short hash, author, date, summary) that `EditMouseMove` shows through the hover timer. Uncommitted lines are shown as "Not committed" in italics. A click on a cell (`EditClickGutter`, through `OnClickGutter`) shows its commit: `ShowBlameCommit` sets Base to `TGittanRepo.CommitRange`, the range from the parent (or from the empty tree for a root commit), and `BaseLabel` names it "vs commit abc1234" while `FBlameRange` matches; Compare With > HEAD (Working Tree) goes back.
- Go > Code History (Cmd+Shift+H) shows how a piece of the shown file changed over its last commits (`umain.history.inc`, `gittan.history.pp`): the piece as it is now with the past of every line under it. The piece is the selection when it spans more than one row (a word selected by Go to Symbol is not it), else the innermost code tree range around the caret (`EnclosingRange`, the fold ranges with `DisplayInTree` as `CodeTree` reads them, the end row from the range's `EndIdx` token), else the whole file as the range 1..`WholeFileLines`, which git clamps. `ChunkLines` maps the editor rows to file lines in the commit the history starts from (`HistoryRef`: the right commit of a range, else the base, HEAD by default) through `FNewNum` or `FOldNum`, so lines added in the work tree do not shift the range; rows that are all new have no history. `TGittanRepo.LineHistory` runs `git log -L from,to:path [ref]` (or `git log -p -- path` with from 0) with `--format=%x01%H%x1f%an%x1f%at%x1f%s`, and `TGittanHistory.Parse` reads the commits with their hunks (`TGittanHistoryCommit`: a `TGittanBlameCommit` plus `TGittanHistoryHunk`s with the start lines from the `@@` header). `TGittanHistoryJob` runs it in a thread like the blame job (abandoned jobs share `FBlameZombies`, a `TGittanJobReaper` of `gittan.job`, tested, which frees a job once its thread has ended, `FreeFinished` from `FreeBlameJobsAsync`, and waits for the rest when it is freed), `HistoryStep` (5) commits at a time plus one to know whether there are older ones; the changes not committed yet come first as a commit of their own (`AddUncommittedHistory`, the file's diff against HEAD cut to the range, only while the base is HEAD). `TGittanHistory.Layers` (tested) chains the hunks newest first: the new side of the newest commit is the current text, a commit's deleted lines are paired in order with the added lines in their place as their earlier versions, unpaired deleted lines are removed lines kept after the line before them, and the old side of each commit is matched by text, in order, to the new side of the next older one. The result is `TGittanHistoryRow`s: a current line (with its number in the newest version), the older versions under it, and removed lines, each with the commit it comes from (-1 when older than the history). `BuildHistoryView` puts them into the change view's fields (`GapFrom` holds the row's commit, so the blame band, hint and click work through `CommitOfRow` in `umain.blame.inc` without a blame, and a band click goes through `ShowHistoryCommit`): a legend row per commit first (`rowCommit`, `bmCommit`, bold through `MarkHeader`, the text from `HistoryHeaderText`: a swatch colored by `MarkSwatch`, short hash, date, author, summary, lines added and deleted; the author and summary composed with `GetDarwinNormalizedFilename`, since macOS gives git a decomposed name the editor would paint as two characters), a filler, then the rows: each tinted by its commit through bookmark kind `bmHistoryBase` + commit (`EditCalcBookmarkColor` maps it to `HistoryColor`: a fixed palette of six hues taken in turn, in three tones from `THistoryTone`, faint for the rows, stronger for the words and darker in light mode (lighter in dark) for the swatch, which is text and keeps 3.4:1 or more against the background; each tone is one OKLCH lightness and chroma, so no hue looks lighter than the others, and the hues keep away from the diff's red and green), an older version in italics and a removed line struck through (attribs tagged `tagHistoryStyle`), and the words that changed between a version and the one before it shaded in the strong tint (`MarkHistoryWords`, tag `tagHistoryWord` with the commit in `TagEx` so `RecolorWords` can follow the theme). A band of its own next to the text (`gutterTagInitial`, `InitialCols` wide, shown by `SetInitialBand` from `ApplyBlame` in the history view only, whatever View > Blame says) puts the author's initial on every row with a commit, legend rows included (`DrawInitials`, through `CommitOfRow`): the first letter of the composed name in upper case (`NameInitial`) on a flat rounded badge in the commit's row tint, the letter bold in its swatch tone; the changes not committed yet take the initial of `TGittanRepo.UserName` (`git config user.name`, read into `FHistoryUser` by `BuildHistoryView`), and a line older than the history gets none. A click or the hint on the band works as on the blame band. A last `rowMore` row fetches `HistoryStep` more while git had more. `EditMouseUp` sends a click to `HistoryClick`: a legend row shows the commit against its parent and opens the file at the hunk's first line, the more row fetches more at the same scroll position. `RefreshRepository` runs the job again for the same piece. `ChangeBlocks` skips legend rows, so the navigator counts the tinted runs. Side by Side and Hide Unchanged Lines do not apply to the view. After a commit the stored line range may no longer match the function; the command is run again from the file then.
