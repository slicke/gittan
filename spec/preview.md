# Markdown, HTML and SVG preview

Read this when touching `gittan.mdpreview`, `gittan.richdiff`, the Preview toggle, or how an SVG is drawn in the change view.

- View > Preview (Cmd+Shift+V, `MarkdownPreview` in the settings, off by default) shows a Markdown, HTML or SVG file (`IsPreviewPath`: `IsMarkdownPath` for `.md`, `.markdown`, `.mdown`, `.mkd`, `.mkdn`, `IsHtmlPath` for `.html`, `.htm`, `IsSvgPath` for `.svg`) drawn beside the editor, in the change view (the new side: the diff lines that are not deleted ones) and in a file opened by itself (`umain.mdpreview.inc`). `TGittanMarkdownPreview` (`gittan.mdpreview.pp`) is a `TInkPage` from LazInk with the editor's colors (`SetColors` from `ApplyTheme`), its font size at the editor's zoom, raw HTML allowed (a README's badges and `<details>`) and images no wider than the column. The page is loaded with the file's `file://` URI as its base, so relative images load from the work tree; a link to a heading scrolls, one to a local file goes to `ShowRepoFile` (inside the repository) or `OpenFile`, anything else to the browser. Loading the same text again does nothing and the same file keeps its scroll, so a refresh after the file changed on disk does not jump to the top; a repository file open to edits follows typing after `MdPreviewPause`.
- `ShowFile` picks LazInk's `LoadMarkdown` or `LoadHTML` by the extension. LazInk draws no SVG, so `OnResource` (`PageResource`) draws it with BGRABitmap's `TBGRASVG` (`RenderSvg`) as a PNG: an SVG file is shown as an `<img>` of a `gittan-svg:<n>.png` URL, numbered per load since LazInk keeps a picture by its URL, a small one (an icon) a whole number of times larger, up to 256 pixels on its longer side or 8 times, and drawn at the screen's pixels; an `.svg` image a Markdown or HTML page links to is drawn at its own size. A local picture in a format LazInk does not read itself (`PageReadsImage`: png, gif, jpg, jpeg, bmp, ico and webp are its own) that the image view shows (`IsImagePath`), a TGA, PSD or OpenRaster file say, is decoded by `DecodeImage` and handed over as a PNG (`RenderImage`). In the change view an SVG is drawn twice (`ShowChange`, `ShowSvgChange`): the old side (the diff lines that are not added ones, `gittan-svg:<n>-old.png`) over the new, at one zoom from the larger of the two, each under a Before or After caption with its size in pixels and bytes, the new one with how many of the pixels differ when the sizes match (both drawn at their own size and counted by `DifferingPixels` and `DifferingNote` from `gittan.imagediff.pp`, which the image view uses too); a side without a version says "Not in this version" in a dotted box, one that cannot be drawn says so. The text diff stays in the editor beside it. A changed Markdown or HTML page (one with an old version that differs) is shown with its changes marked, as a rich diff (`ShowRichDiff`, `gittan.richdiff.pp`): `MarkRichDiff` reads both versions' HTML (Markdown through LazInk's `MarkdownToHTML` with `imoRawHTML`, as `LoadMarkdown` converts it) into LazInk's DOM, cuts each into blocks (an element whose children are all inline, a table row; a list, quote, table or a list item with a nested list is cut further, its inline text before its blocks moved into a `<div>`), keyed by their HTML with white space collapsed, and matches them by their longest common subsequence after the shared start and end (unmarked past `MaxCells`); in each stretch between matches the first new blocks pair with the first old ones and get `gittan-changed`, the rest `gittan-added`, and the old ones left over are put back as copies with `gittan-deleted` after the new block before them (inside copies of their containers when that one sits in another kind, so an item goes into a list and a row into a table). The page is loaded with `LoadHTML`; `ApplyStyle` draws the classes as a three-pixel bar in the margin in GitHub's diff colors (`FDark` picks them; a table row and a list item get a tint instead), a deleted block struck through. An added page is shown as it is. LazInk needs LazUtils, which the fpc-only test build has not got, so the unit is in `src/ui` and untested there.
- The file header has a Preview toggle (`SetToggle`, `OnToggle`), a pill left of the action pills tinted in the accent while on, which stays in the header when ShowControls hands the pills to the macOS toolbar. `UpdatePreviewToggle` (from `UpdateStatus` and both menu handlers) sets it for the file `PreviewTogglePath` names: a `.po` file in the change view without conflicts, opened by itself or in the translation view toggles View > Translations, a file the preview draws toggles View > Preview; any other view shows none, and `SetFile`/`SetTitle` take it away. Its tooltip names the menu item's shortcut.
- `FMdPreview` and `FMdSplitter` are `alRight` in `EditorPanel`, at `FMdRatio` of its width. `ShowEditor` calls `UpdateMarkdownPreview`, which shows or hides them; the views that hide the editor (summary, image, binary) call `HideMarkdownPreview`. The side-by-side view shares what is left (`SidesWidth`).
