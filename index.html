What I haven't found anywhere else

Most of what Gittan does, every git client does. These things I have not found in TortoiseGit, SourceTree, Fork, GitKraken, Tower or the git views of the IDEs. If you know one that has it, tell me and I will take the line out.

Put a change into the commit it belongs to

Hover a change and press Put into Its Commit: Gittan finds the commit of your branch that last wrote those lines and folds the change into it, so a round of fixes lands in the commits it fixes, not in a “fixes” commit on top. Pushed commits are never rewritten, and Undo takes it back. The command line has git absorb; no client I know has it.

Then commit it

Commit, sync and merge, from the diff

The work that follows a change happens where you read it. Anything that would throw work away asks first, and nothing is merged or rebased unless you ask for it. The whole workflow has eighteen views.

  1. Commit what you ticked

    Tick the files that belong together and commit with ⌘↩, or commit a block, or only the lines you select, line by line, and leave the rest for the next commit. There is no index to think about.

    Committing, in the workflow

  2. Pull and push from the status bar

    Its middle button is always the next step: Pull here, with one commit behind and two ahead. Force Push takes a lease and says how many of the remote's commits it replaces, and with gh signed in the branch's pull request and its checks sit beside them.

    Pull and push, in the workflow

  3. Resolve what conflicts

    A merge that stops names its conflicts. Use Mine, Use Theirs, or the merge editor: yours and theirs side by side, the result under them, conflict by conflict, and Branch > Undo if it was a mistake.

    The merge editor, in the workflow

Before you install
  • GitGittan runs the git command line tool, so git 2.30 or later must be installed and on your PATH.
  • WindowsThe Windows installer needs no administrator for yourself alone, and adds Open in Gittan to folders' menu and the gittan command; it is not signed, so SmartScreen warns at first: More info, then Run anyway. The x64 build runs on Windows 11 on Arm too, emulated; Gittan-windows-arm64.zip runs there natively.
  • LinuxOn Linux the .deb (Debian, Ubuntu, Raspberry Pi OS 64-bit) and the .rpm (Fedora, openSUSE) put Gittan in the desktop's menu with its icon, and the .tar.gz runs where you unpack it; all use GTK 3, which every common desktop already has.
  • macOSThe macOS build is signed ad hoc, so macOS blocks it at first: drag it to Applications, then run xattr -cr /Applications/Gittan.app in Terminal.
  • HaikuOn Haiku (64-bit), Gittan-haiku-x86_64.hpkg is a package: pkgman install Gittan-haiku-x86_64.hpkg brings Qt 6 and git with it, and Gittan is then in the Deskbar menu under Applications. Without installing, Gittan-haiku-x86_64.tar.gz runs where you unpack it and needs Qt 6: pkgman install libqt6pas.
  • FreeBSDOn FreeBSD 15.1 or later (amd64), Gittan-freebsd-amd64.tar.gz runs where you unpack it and needs GTK 3 and git: pkg install gtk3 git. The Windows on Arm, Haiku and FreeBSD builds are added to a release when they build, so the newest release may lack one; the Releases page then has the latest that has it.
  • Other versionsEvery release, with what changed in it, is on the Releases page. To try changes before they are released, open the newest run on GitHub Actions and download the file for your system under Artifacts, which needs a GitHub account.
