Workflow

Commit, sync and merge

Gittan started as a viewer, and it still puts the diff first. Now the work that follows happens there too. Anything that would throw work away asks first, and nothing gets merged or rebased unless you ask for it.

Commit what you see

Every changed file in the tree has a check box. Untick what should wait, or leave one block of a file out with Skip in Commit, write the message at the bottom of the panel and commit with ⌘↩. Files go in as the diff shows them, and your hooks and signing run as git is set up to. Amend picks up the last message, and a branch that can be pushed offers Push right after.

Says what went wrong

A command that failed tells in a banner over the diff, with git's reason, Details and Copy, in place of a dialog in the way. It stays until you close it. A push or pull that went through shows in green and goes away on its own.

Push failed! [rejected] main → main (fetch first)DetailsCopy
✓ Pushed 2 commits on main

Resolve conflicts

Your side, the base and theirs each get a color. Take one side for a whole file, or one conflict at a time with ⌘⇧R: mine, theirs or both. "Mine" is always your own work, in a rebase too. The last one resolved takes you to the next file, then to Commit or Continue.

Stashes

⌘⌥S stashes the changes, or only the ticked files, untracked ones along. The chip in the status bar lists them with branch and age; pick one to see what it holds, then apply, pop or drop it, or branch from it.

Pull, push and fetch

⌘⇧L pulls, ⌘⇧P pushes, ⌘⌥F fetches, or use the buttons in the status bar. A pull only fast-forwards unless your git config says otherwise; a branch that went its own way asks Merge or Rebase. After a rebase, ⌘⌥⇧P force-pushes with a lease, so nobody else's commits are lost.

Branches

⌘B switches, the list makes new ones and cleans up the ones whose remote branch is gone. When local changes stand in the way, Gittan names the files and offers Stash and Switch or Bring Changes Along. Set Upstream pushes a new branch or picks what it tracks.

Merge and rebase

See what a branch would bring, in either direction, then merge or rebase from that very comparison. Choose Commits… turns it into an interactive rebase. A rebase says first when the next push will have to be forced, and the status bar counts its steps.

Revert, and undo it

Put a file, or every changed file in a folder, back as HEAD has it. Gittan keeps a copy first, so Undo Revert brings your edits back if that was a mistake. Rename or Move and Remove from Git work on the file menu too.

Tags

Branch > Tags… lists them newest first. Make one at HEAD or at any commit, check one out, branch from it, push it, or delete it here and on the remote.

Patches

Write a commit, or every commit between two, as patch files, with a cover letter if you like. Apply Patches… commits mailed patches one by one, or only changes the work tree.

Clone, init and remotes

Clone a repository, its submodules too, or make a folder a new one, from the welcome view or the File menu. The Remotes dialog adds, renames and removes remotes and sets their push URLs.

Reflog

Branch > Reflog… shows where HEAD has been, and marks the commits nothing else reaches any more. Pick one to see it, branch from it or reset back to it.

Diff

See what changed

The diff is where Gittan starts. It shows the difference between your work tree and any commit, and keeps that view fresh while you edit in whatever editor you like.

Live view

A background thread polls the repository every two seconds. Save a file in your editor and the tree, the counts and the diff update on their own.

Syntax highlighting

Lexers from the CudaText collection, picked by file name. Colors are tuned for both light and dark backgrounds.

Preview

A Markdown, HTML or SVG file can be drawn beside its diff as it will look, with no browser engine. The Preview pill in the file header, or ⌘⇧V, turns it on, and it follows the file as it changes.

Hide unchanged lines

Keep only the changed lines with 1, 3, 5 or 10 lines of context. Click a gap to open it. Highlighting still covers the whole file, so nothing colors wrong.

Side by side or unified

Old on the left, new on the right, scrolled in step, each side numbered from its own file. Or a single view with deleted lines kept in place.

Compare with any ref

Diff against HEAD by default, or pick a branch, a tag, a commit or a snapshot. The tree, the counts and every file diff follow the base you chose.

Dark mode

Follows the desktop theme. On Windows the native tree, menus and dialogs turn dark too, so the whole window matches, not only the editor.

Scroll on to the next file

A file opens at its first change. Keep scrolling at the bottom of it and the next one pulls in. Step changes with F7, files with F8, or click a row in the summary.

Opens in your editor

Right-click a file to copy its path, reveal it in Finder or the file manager, or open it in your editor. ⌘⌥T opens a terminal. Settings (⌘,) has a page for the font, the tab width and the syntax theme, and one for the editor, the terminal, git and gh.

Review, skip or discard a block

Rest the mouse on a changed row and pills appear. Reviewed shows the block as plain code for the rest of the session, so the diff shrinks as you read it. Skip in Commit leaves it for a later commit. Discard puts it back as HEAD has it, after asking.

Fits the file

Word wrap, ignore whitespace, zoom, and the tab width git uses. The editor font is the platform's monospaced one, sized for the screen, until you pick another.

Folding

Fold functions, classes and other blocks the lexer knows, in the file view and in the unified diff.

History

See how it got there

Every line has a past. Gittan reads it from git and lays it next to the code, so you can tell who changed what, when, and why it looks the way it does.

Code History

Put the caret in a function or select a few lines, then ⌘⇧H. Each line gets its earlier versions under it, one color per commit.

Commit graph

Graph in the sidebar, or ⌘3, draws the branches with what is not pushed or not pulled yet. Type to search it: words, author:, since:, until: and path:. A file's Show History is the graph of the commits that touched it.

The repository at a glance

Repository in the sidebar, or ⌘⇧I, opens a page about the repository itself: the branch and its upstream, then tiles for the commits, branches, tags, files, submodules and size, each a click away from its list. Under them the remotes, and the authors with their share of the commits.

Compare branches

A branch's menu shows what it changed since it left yours, or what yours changed since it left it. Mark a commit in the graph and compare another with it, or give Compare With > Other any range, such as v1..v2.

Snapshots

Take a snapshot of the work tree with ⌘⇧N and compare against it later, to see what the last round of edits did without committing anything.

Go to definition

Hover a word to see where it is defined, and jump there with F12. Gittan finds it through the lexer's code tree, with no language server to set up.

Find a symbol

List the symbols of the shown file with ⌘T, or of the whole repository with ⌘⇧T, and type a few letters to get there.

Pull request reviews

With the gh CLI signed in, the status bar shows the branch's pull request and its checks, and the review comments appear under the lines they are about.

Submodules

Every submodule in a section of its own, with the new commits on its remote. Gittan asks again every five minutes without fetching, and updates, syncs or adds submodules from File > Submodules.

Browse any commit

Browse Files… on a commit, a tag or a reflog entry shows the whole tree as it was then. Open a file from it, or save it.

Statistics

The graph's Statistics toggle counts the commits per week and per author, for the whole log or only what the search finds.

Any commit, explained

Click a commit in the graph and the summary shows it against its parent, under a card with its message, author and age, and a way back to the working tree.

Gittan runs the git command line tool, so git 2.30 or later must be installed and on your PATH. On Linux it uses GTK 3, which every common desktop already has. The macOS build is signed ad hoc, so macOS blocks it at first: drag it to Applications, then run xattr -cr /Applications/Gittan.app in Terminal. Older builds and release notes are on the Releases page. Every push to main is also built on GitHub Actions, where the artifacts of the newest run are the current development build.

Source

Build from source

Gittan is a Free Pascal application built with Lazarus. The editor (ATSynEdit), the highlighter (EControl), the lexers, MetaDarkStyle and LazInk are git submodules, so fetch them and register their packages with Lazarus before the first build.

  1. Install Lazarus and FPC

    Lazarus 5.0 with FPC 3.2.2 or later. On Linux also the GTK 3 headers: libgtk-3-dev on Debian and Ubuntu, gtk3-devel on Fedora. On macOS, the Xcode Command Line Tools.

  2. Clone with the submodules

    git clone --recursive https://github.com/slicke/gittan.git
cd gittan

# Cloned without --recursive, or pulled a submodule change?
git submodule update --init --recursive

  3. Register the vendored packages, once

    Lazarus has to know where the packages are. Add them in this order, since each depends on the ones before it.

    for p in ATFlatControls/atflatcontrols/atflatcontrols_package.lpk \
         EncConv/encconv/encconv_package.lpk \
         BGRABitmap/bgrabitmap/bgrabitmappack.lpk \
         ATSynEdit/atsynedit/atsynedit_package.lpk \
         EControl/econtrol/econtrol_package.lpk \
         ATSynEdit_Ex/atsynedit_ex/atsynedit_ex_package.lpk \
         metadarkstyle/metadarkstyle.lpk \
         lazink/lazink.lpk; do
  lazbuild --add-package-link vendor/$p
done

    On Windows run the same lazbuild --add-package-link for each file in PowerShell, or open each .lpk once in the IDE (Package > Open Package File), which registers it.

  4. Build and run

    make          # cocoa on macOS, gtk3 on Linux
make run

# Windows, where there is no make:
.\make.ps1
.\make.ps1 run
  • The Makefile finds lazbuild in /Applications/lazarus on macOS when it is not on PATH; make.ps1 looks in C:\lazarus and C:\fpcupdeluxe\lazarus.
  • Every build copies the lexers from vendor/CudaText-lexers into lexlib/. A build from the Lazarus IDE does not: run make lexlib once.
  • Already built Gittan before? Register metadarkstyle.lpk and lazink.lpk too; every platform needs both, though only Windows uses the first.
  • On macOS, "malformed method list atom" from the linker means an old ld: update Xcode or the Command Line Tools.
  • Details for every platform are in AGENTS.md.
